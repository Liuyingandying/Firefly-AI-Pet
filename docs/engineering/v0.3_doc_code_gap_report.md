## 0. 结论摘要

v0.3 的**核心运行时已基本实现**（记忆域 + 对话存储 + 关系状态 + 组合根 + 记忆面板 + 独立聊天窗），但相对设计文档存在 **4 类实质偏差**，且 **8 个规格/文档明确要求的能力缺失**。全部代码**未提交**（git 工作区为脏，详见 §6）。

最关键的三处失配：

1. **Bond 状态被大幅简化** —— 规格的 `intimacy`（亲密度 Lv.1–5）、时间戳、`interaction_count`、约定状态对象全部删除，改为 `trust + familiarity + milestones + 字符串约定`。
2. **滚动摘要 / 双层归档整条链路缺失** —— ConversationStore 无 `archive` 层、无 `summarize_and_archive`，规格 §1.3 的"窗口溢出 → 压缩摘要 → 写 `shared_experience`"未落地。
3. **隐私 / 一致性硬件缺失** —— 红线过滤、去重合并、`reconcile()` 对账、`config/companion.json` 配置模块，四个硬性项均未实现。

## 2. 相对设计文档的实质偏差（文档已过时，应按实况更新）

### 2.1 Bond 状态被简化（最大偏差）

| 维度 | 设计文档 §6 | 实况 |
|------|------------|------|
| 字段 | `intimacy` `trust` `familiarity` `phase` `pending_promises[{text,made_ts,status}]` `first_met_ts` `last_interaction_ts` `interaction_count` | `phase` `trust_level` `familiarity_level` `shared_milestones` `pending_promises(纯字符串)` |
| 亲密度 | `intimacy` 展示为 Lv.1–5 | **删除**，无 intimacy 概念 |
| 时间戳/计数 | `first_met_ts`/`last_interaction_ts`/`interaction_count` | **删除** |
| 约定结构 | 对象 `{text, made_ts, status: open\|kept\|missed}` | 纯字符串 tuple（无 made_ts、无 status） |
| 里程碑 | 无 | **新增** `shared_milestones` |
| 信号集 | `TURN_COMPLETED` `THANKED` `SELF_DISCLOSURE` `TAUGHT_FIREFLY` `CORRECTION` `PROMISE_MADE/KEPT/MISSED` | `TURN_COMPLETED` `THANKED` `CORRECTION` `SHARED_MILESTONE` `PROMISE_MADE/KEPT/MISSED` |
| 阶段分公式 | `0.5·intimacy + 0.3·trust + 0.2·familiarity` | `(trust + familiarity) / 2` |
| 文件名 | `relationship.json` | `bond_state.json` |
| render | `BondStateEngine.render()` | 由 `BondContextBuilder.build()` 承担（不暴露原始 float） |

**结论:** `intimacy`、时间戳、`interaction_count`、约定状态对象四项规格字段未落地。需决策：按简化版固化，还是补回规格版。

### 2.2 Conversation Store 重构

- 设计文档 §5.2/§5.3 的"双层（working + archive）+ 滚动摘要"未实现。
- 实况为**多会话**结构 `{version, sessions: {session_id: {turns, summary}}}`，**无 `archive` 层**。
- 摘要由 `set_summary()` 外部注入（"never generated here"），**无 `summarize_and_archive`**。
- 新增 `switch_session`/`create_session`/`list_sessions`/`delete_session`/`append_exchange`（文档未预见）。
- 窗口上限 `DEFAULT_MAX_MESSAGES = 40`（约 20 轮），但无 token 软上限。

### 2.3 记忆域扩展

- `MemorySource` 多出 `migrated`（迁移路径新增，见 §7）。
- `mem0_client.py` 未删除（设计文档 §8.2 说删），被 `memory_manager.py` 保留作 legacy 兼容（`LegacyClientSemanticAdapter`/`LocalMem0Client`）。
- `memory_manager.get_memory_context` 未改走 `MemoryPromptBuilder`，自行拼字符串。
- 新增 `memory/suggestion/`（`MemoryCandidateDetector` 确定性规则 + `SuggestionService` 待确认队列）——即规格 §3.2 触发器 B，设计文档只标"P1/default-off"，实际已实现。
- `memory/__init__.py` 未导出 `SuggestionService`/`MemoryCandidateDetector`。

### 2.4 UI 偏差

- `ui/memory_panel.py` 为三标签（Memory / Narrative / Bond）+ 可选"待确认"，非设计文档设想的单一记忆列表。
- `app.py` 已把 Companion **对话**路径装配进 Short Ask（`CharacterConversationRunner` 作为 `firefly` agent），但 **`ui/memory_panel.py` 未接入任何入口**；`ui/companion_chat_window.py` 是独立最小入口（`python -m ui.companion_chat_window`）。
- 新增 `Narrative` 概念（运行时默认不注入，见 §7）。

## 5. 依赖方向核验

设计文档 §1.2 要求：`memory/` 不 import `core/`/`ui/`；`core/` 不 import `ui/`；仅 `mem0_adapter.py` import `mem0`。

- ✅ `memory/` 自包含（`records`/`repository`/`service`/`write_guards`/`mem0_adapter` 均只 import 彼此 + 标准库）。
- ✅ 仅 `mem0_adapter.py` 在 `_default_backend_factory` 内惰性 `import mem0`。
- ⚠️ `core/bond_state.py` import `core/bond_rules.py`（同层，合理）；`core/companion_runtime.py` import `memory/*` 与 `character/*`（`core → memory` 单向，符合 §1.2 允许的"ConversationStore 依赖 MemoryService"方向）。
- ✅ `ui/` 是唯一 import Qt 的层。
