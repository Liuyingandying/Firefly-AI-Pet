# Firefly AI Pet v0.3 Engineering Implementation Design

**文档性质:** 工程实现设计(施工图),供 Codex 下一阶段开发使用
**版本:** v0.3
**日期:** 2026-08-25
**前置文档:** `docs/design/v0.3_companion_product_spec.md`(产品规格)、`docs/memory_architecture_review.md`(v0.2 审查)
**约束:** 本文档只做设计,不含实现代码;所有接口以"方法契约"形式描述,不写具体实现。

---

## 0. 目标与交付

把产品规格的五大支柱,映射为**可被 Codex 直接实现的模块、接口、数据模型、测试与迁移步骤**。本文档的验收对象是"Codex 能否仅凭本文档 + 产品规格,无歧义地完成施工"。

三条贯穿性的工程决策(先记住,后文展开):

1. **真相源分离:** `MemoryRecord` JSON 索引是记忆的真相源,Mem0 退化为"向量检索底材"。所有生命周期/权限/审计操作只针对索引,不碰 Mem0 内部结构。
2. **状态归系统:** `BondState` 由确定性规则引擎独占写入,LLM 只读。这是防注入的根本手段,也决定了接口形态(引擎 `apply(signal)` 无 LLM 参与)。
3. **离线优先测试:** 所有核心模块 Qt-free、可用 fake 离线测试;Mem0/Qdrant 只出现在一个窄适配器里,通过契约接口被替换。

## 1. 模块拆分

### 1.1 目标模块树

```text
memory/                          # 记忆域(零 Qt 依赖)
  records.py                     # ★ MemoryRecord + 枚举 + 校验
  repository.py                  # ★ MemoryRepository(抽象) + JsonMemoryRepository
  mem0_adapter.py                # ★ Mem0Adapter(从 mem0_client.py 重构而来)
  service.py                     # ★ MemoryService(编排:双写/去重/权限闸门)
  write_guards.py                # ★ 红线过滤 + 否定拦截 + 分类推断
  memory_prompt_builder.py       # (现有,扩展) 格式化层,补 relationship 类别
  mem0_client.py                 # (现有,将被 mem0_adapter.py 取代)
  memory_manager.py              # (现有,演化) 见 §8 迁移
  __init__.py                    # 公共导出(向后兼容)

core/                            # 核心服务(零 Qt 依赖)
  conversation_store.py          # ★ ConversationStore + Turn + 滚动摘要
  bond_state.py                  # ★ BondState + BondStateEngine + 信号
  companion_config.py            # ★ CompanionConfig(配置加载/校验)
  conversation_runtime.py        # (现有,扩展) 接 ConversationStore + BondState
  session_manager.py / session_store.py  # (不动) 原生 session,与 Firefly 对话无关

ui/                              # UI 桥接
  memory_panel.py                # ★ 记忆管理面板(查看/删除/清空/导出)
  character_conversation_runner.py # (现有,改造) _history 换 ConversationStore
  short_ask.py                   # (现有,不动核心,加记忆入口信号)

character/                       # (不动) 人格 yaml 保持静态
```

### 1.2 分层与依赖方向(单向,禁止反向)

```text
UI (ui/)                     ← 唯一允许依赖 Qt 的层
  │ 依赖
Core (core/)                 ← 业务服务,零 Qt,可独立测试
  │ 依赖
Memory (memory/)             ← 记忆域,零 Qt,零 core 依赖
  │ 依赖
Mem0Adapter                  ← 唯一接触 Mem0/Qdrant/FastEmbed 的边界
```

**规则:**

- `memory/` 不得 import `core/` 或 `ui/`;`core/` 不得 import `ui/`。
- 只有 `Mem0Adapter` 能 import `mem0` / 触碰 Qdrant/FastEmbed。
- `ConversationStore`(core)依赖 `MemoryService`(memory)仅用于写滚动摘要——此依赖单向、可注入 fake。
- `BondState`(core)不依赖记忆库;它被 `ConversationRuntime` 读取后,**渲染结果**交由 `MemoryService` 注入(见 §6.4),避免 core 反向依赖 memory 的检索逻辑。

### 1.3 模块职责一句话

| 模块 | 一句话职责 |
|------|-----------|
| `records.py` | 定义记忆的"是什么"——字段、枚举、校验、不变式 |
| `repository.py` | 记忆真相源的持久化 CRUD(JSON,原子写) |
| `mem0_adapter.py` | 语义检索的唯一通道,隔离 Mem0 的一切 |
| `service.py` | 编排"写管线的 5 步 + 读管线的检索/注入" |
| `write_guards.py` | 写入前的安全/质量闸门(红线、否定、分类、去重判断) |
| `conversation_store.py` | Firefly 自己的对话持久化(双层) |
| `bond_state.py` | 关系状态的模型 + 确定性演化引擎 |
| `companion_config.py` | 把 `config/companion.json` 变成有类型的配置 |
| `memory_panel.py` | 用户对记忆的主权操作界面 |

## 2. MemoryRecord 数据模型

### 2.1 枚举(全限定、封闭)

| 枚举 | 取值 | 说明 |
|------|------|------|
| `MemoryCategory` | `relationship` `shared_experience` `emotion` `preference` `user_fact` `project` | 6 类,与产品规格 §3.3 对齐 |
| `MemorySource` | `explicit` `suggested` | 显式命令 vs 建议写入 |
| `WritePolicy` | `off` `explicit_only` `ask` `auto` | 写入权限策略,默认 `explicit_only` |

### 2.2 MemoryRecord 字段

| 字段 | 类型 | 必填 | 默认 | 校验/不变式 |
|------|------|------|------|------------|
| `id` | str | ✅ | 系统生成(稳定、可排序) | 非空、唯一 |
| `category` | MemoryCategory | ✅ | — | 必须 ∈ 枚举 |
| `content` | str | ✅ | — | strip 后非空 |
| `source` | MemorySource | ✅ | `explicit` | 必须 ∈ 枚举 |
| `trigger` | str | ✅ | — | turn_id 或命令类型令牌 |
| `permission` | WritePolicy | ✅ | 写入时策略快照 | ∈ 枚举 |
| `weight` | float | ✅ | 按类别默认 | ∈ [0.0, 2.0] |
| `created_ts` | int(ms) | ✅ | 写入时刻 | > 0 |
| `updated_ts` | int(ms) | ✅ | = created | ≥ created_ts |
| `last_accessed_ts` | int(ms) | ✅ | = created | ≥ created_ts |
| `retention_half_life_days` | float | ✅ | 按类别默认 | > 0 |
| `vector_id` | str \| null | ❌ | null | 关联 Mem0 向量的外键 |

**类别默认表(权重 / 半衰期):**

| category | weight | half_life_days |
|----------|--------|----------------|
| relationship | 1.5 | 90 |
| shared_experience | 1.2 | 60 |
| emotion | 1.0 | 7 |
| preference | 0.9 | 14 |
| user_fact | 0.8 | 30 |
| project | 0.6 | 14 |

### 2.3 记录索引 Schema(JSON,真相源)

```text
runtime/companion/memory_records.json
{
  version: 1,
  records: [ { ...MemoryRecord 全部字段... } ]
}
```

**不变式(必须由 repository 强制,违反即校验失败):**

1. `id` 全局唯一,且 `id` 与 `vector_id` 形成 1:1(可重建)。
2. `content` / `category` / `source` / `trigger` 均非空合法。
3. `updated_ts >= created_ts`,`last_accessed_ts >= created_ts`。
4. 单条记录损坏不丢整体(跳过);整个文件损坏降级为空索引,不抛异常。

## 3. Repository 接口

### 3.1 抽象接口 MemoryRepository

仅定义契约,不绑定存储实现(便于测试 fake、未来换 SQLite)。方法如下:

| 方法 | 参数 | 返回 | 职责 / 边界行为 |
|------|------|------|----------------|
| `add` | record | 生成的 id | 追加记录;id 冲突抛错;落盘原子写 |
| `get` | record_id | MemoryRecord \| null | 按 id 取;同时更新 `last_accessed_ts` |
| `update` | record_id, patch(部分字段) | MemoryRecord | 部分更新;自动 `updated_ts = now`;未知字段忽略 |
| `delete` | record_id | bool | 删除;不存在返回 false |
| `clear` | — | int(删除数) | 清空全部 |
| `list` | category?/source?/before_ts? | list | 按过滤条件列举,按 `created_ts` 降序 |
| `all_ids` | — | set[str] | 全部 id(供 Mem0 对账) |
| `export` | — | dict | 全量序列化(供导出/备份) |
| `import` | data | int(导入数) | 校验后批量导入;坏记录跳过并计数 |

### 3.2 实现 JsonMemoryRepository

- 存储路径:注入 `runtime/companion/memory_records.json`。
- **原子写:** 临时文件 + `os.replace`(复用 `SessionStore` 模式)。
- **健壮性:** 顶层 `version` 校验;未知大版本 → 空索引;单条坏记录 → 跳过;文件损坏 → 空索引。
- **并发:** 单进程内互斥锁(与现有 `MemoryManager` 的单例锁同风格);不引入跨进程锁。
- **注意:** 该类**不得 import mem0**;`vector_id` 只是字符串字段,由 `MemoryService` 负责与适配器对账。

### 3.3 对账(Reconciliation)

`MemoryService` 提供 `reconcile()`:
- 遍历 `repository.all_ids()`,凡 `vector_id` 为空者,触发补写向量(写失败可重试,不影响索引可读)。
- 对 Mem0 中孤儿向量(无对应 id),惰性清理。
- 目的:保证双写最终一致,且索引永远是权威。

## 4. Mem0 Adapter 设计

### 4.1 定位

`Mem0Adapter` 是系统里**唯一** import `mem0` 的地方。它把 `mem0_client.py` 的现有能力收窄为一个"语义检索契约",并强化隐私隔离。

### 4.2 接口契约

| 方法 | 参数 | 返回 | 说明 |
|------|------|------|------|
| `add` | text, metadata | vector_id | 写入向量 + 元数据;`infer=False` 恒成立 |
| `search` | query, limit | list[Hit] | Hit = {vector_id, text, metadata, score},按 score 降序 |
| `delete` | vector_id | bool | 删除单条向量 |
| `clear` | — | int | 清空集合 |
| `health` | — | bool | 惰性初始化成功与否 |

### 4.3 隐私不变式(必须保留,逐条测试)

1. `infer=False` 恒成立——永远绕过 Mem0 的 LLM 提取。
2. `MEM0_TELEMETRY=false` 在 import mem0 前设置。
3. `MEM0_DIR` 指向本地 `storage_dir/mem0-home`。
4. LLM 占位符指向 loopback(`127.0.0.1:9`),即使未来上游行为改变也不会外发记忆文本。
5. 本地 Qdrant(文件)+ FastEmbed(`bge-small-zh-v1.5`,512 维,ONNX),模型缓存本地。
6. 惰性初始化:首次调用才 import/构造,失败抛出受控异常,不崩溃。

### 4.4 从 mem0_client.py 的改造点

| 现状 | 目标 |
|------|------|
| `LocalMem0Client.add/search/_client` | 收窄为 `Mem0Adapter.add/search/delete/clear/health` |
| 返回原始 Mem0 dict | 统一为 `Hit` 结构,屏蔽 Mem0 内部形态 |
| 直接由 `MemoryManager` 调用 | 只由 `MemoryService` 调用,`MemoryManager` 不再直连 |
| 无 delete/clear | 补齐,支撑用户"删除/清空记忆"主权 |

**契约测试关键:** `Mem0Adapter` 的测试必须通过一个 **fake 向量后端** 验证契约,不依赖真实 Mem0(真实 Mem0 测试标记为可选集成测试)。

## 5. Conversation Store 设计

### 5.1 定位

Firefly **自己**的对话持久化,与 `SessionManager`(原生 Claude session / Codex thread)彻底解耦。

### 5.2 双层模型与数据结构

```text
runtime/companion/conversation.json
{
  version: 1,
  conversation_id: "firefly-main",
  turns:  [ { role, content, ts } ],   # working 工作窗口(有界,注入 Prompt)
  archive: [ { role, content, ts } ],  # 归档(落盘,不注入)
  summary: str                          # 滚动摘要
}
```

### 5.3 接口契约 ConversationStore

| 方法 | 参数 | 返回 | 职责 |
|------|------|------|------|
| `append_turn` | role, content | None | 追加一轮;触发窗口溢出检查 |
| `load_working_window` | — | list[Turn] | 返回当前工作窗口(≤ K 轮) |
| `window_size` | — | int | 当前工作窗口轮数 |
| `summarize_and_archive` | — | str \| null | 溢出轮移入 archive,更新 summary;返回新摘要(供 service 写 shared_experience);无溢出返回 null |
| `clear` | — | None | 清空 turns + archive + summary,**不碰长期记忆** |
| `has_history` | — | bool | 是否有任何对话记录(驱动 UI"续聊"徽标) |

### 5.4 窗口与摘要策略

- **窗口上限 K:** 默认 20 轮,由 `companion_config` 配置;另设 token 软上限(默认约 6000 token),达到即弹性收缩窗口(从最旧轮开始逐轮弹出)。
- **溢出与摘要:** 窗口溢出时,溢出的轮次移入 `archive`;`summarize_and_archive` 把溢出内容压缩为一段摘要写入 `summary` 字段,并把该摘要作为一条 `shared_experience` 记忆交给 `MemoryService`(依赖注入,便于测试)。
- **Summarizer 可插拔:** 默认实现为**确定性模板**(提取关键事实、不调用远程 LLM);可选用本地 LLM 增强。隐私铁律不因此改变——摘要生成永不外发。
- **恢复:** 启动时 `load_working_window()` 恢复工作窗口;`has_history` 恢复续聊状态。

### 5.5 与 ConversationRuntime 的集成契约

`ConversationRuntime.build_messages` 的组装顺序在 v0.3 变为:

```text
[system] IDENTITY
[system] PERSONALITY + POLICY
[system] MEMORY CONTEXT(relationship 恒注入在首位)
[history] 来自 ConversationStore 的工作窗口(有界,不含 system)
[user]   当前消息
```

- 历史来源从"runner 内存 list"改为"`ConversationStore.load_working_window()`"。
- `_normalize_history` 的"禁止 system"校验保持不变。

## 6. Bond State 设计

### 6.1 定位

关系状态是"因记住而不同"的引擎。**核心不变式:引擎独占写入,LLM 只读。**

### 6.2 数据模型 BondState

```text
runtime/companion/relationship.json
{
  version: 1,
  intimacy: 0.0..1.0,
  trust: 0.0..1.0,
  familiarity: 0.0..1.0,     # 派生 = min(1.0, interaction_count / 200)
  phase: "stranger"|"acquaintance"|"familiar"|"trusted"|"companion",
  pending_promises: [ { text, made_ts, status: "open"|"kept"|"missed" } ],
  first_met_ts: int,
  last_interaction_ts: int,
  interaction_count: int
}
```

### 6.3 信号与确定性规则

`BondStateEngine.apply(signal)` 接收一个 `BondSignal`(枚举),按固定规则产生新状态。**规则表(唯一真相,LLM 不参与):**

| Signal | 效果 |
|--------|------|
| `TURN_COMPLETED` | interaction_count += 1;last_interaction_ts = now;familiarity 重算 |
| `THANKED` | intimacy += 0.05;trust += 0.02 |
| `SELF_DISCLOSURE` | intimacy += 0.10;trust += 0.05 |
| `TAUGHT_FIREFLY` | intimacy += 0.05;trust += 0.03 |
| `CORRECTION` | trust += 0.01 |
| `PROMISE_MADE` | 追加 pending_promises(status=open) |
| `PROMISE_KEPT` | trust += 0.08;对应项 status=kept |
| `PROMISE_MISSED` | trust -= 0.05;对应项 status=missed |

**约束:** 所有数值 clamp 到 [0,1];`intimacy`/`trust` 单调有界;`familiarity` 由 `interaction_count` 派生,不单独写。

**阶段迁移(派生分数决定,不单独存储阶段变更逻辑):**

```text
score = 0.5 * intimacy + 0.3 * trust + 0.2 * familiarity
stranger       score < 0.2
acquaintance   0.2 ≤ score < 0.4
familiar       0.4 ≤ score < 0.6
trusted        0.6 ≤ score < 0.8
companion      0.8 ≤ score
```

**亲密度展示等级(由 intimacy 派生):**

```text
Lv.1 [0, 0.2)  Lv.2 [0.2, 0.4)  Lv.3 [0.4, 0.6)  Lv.4 [0.6, 0.8)  Lv.5 [0.8, 1.0]
```

### 6.4 注入契约

`BondStateEngine.render()` 输出自然语言块,作为 `relationship` 类别记忆**恒注入**到 Memory Context 首位:

```text
[关系状态]
- 关系阶段: familiar
- 亲密度: Lv.3(熟悉)
- 有 1 条未完成约定: 明天继续 Firefly 项目
```

- `ConversationRuntime` 每次构建时调用 `render()`,将结果并入 Memory Context(而非让 LLM 自己推断)。
- LLM **只读取**这段文本,**没有任何接口能写回 BondState**。

### 6.5 安全与主权

- 唯一写入口 = `BondStateEngine.apply(signal)`;`signal` 来源是**系统可观测事件**(轮次完成、感谢检测、约定检测),**不是**用户消息原文——因此"把亲密度设成最高"这类注入只是普通用户消息,不触发任何状态写入。
- 用户可 `reset()`(回到 stranger、清空 pending)、可导出。
- 感谢/自我披露/约定等信号的**检测器**是确定性规则或本地启发式,绝不调用远程 LLM。

## 8. 从 v0.2 迁移方案

### 8.1 迁移总原则

- **存量记忆零损失:** 生产环境从未调用 `add_memory`(仅测试数据),因此 Mem0 库中无真实用户记忆;`runtime/memory/` 目录保留不动,新记录索引从空启动,不迁移测试脏数据。
- **向后兼容导出:** `memory/__init__.py` 的公共导出面(`add_memory / search_memory / get_memory_context`)在 v0.3 保留可用,内部改指新 `MemoryService`,避免一次性破坏调用方。
- **分阶段落地:** 严格按产品规格 §6 的 P0 → P1 → P2 顺序,每阶段独立验收,不追求一次重构到位。

### 8.2 文件级映射(现状 → 目标)

| 现状文件 | 处置 | 说明 |
|---------|------|------|
| `memory/mem0_client.py` | 重构为 `memory/mem0_adapter.py`,旧文件删除 | 收窄为检索契约,补 delete/clear |
| `memory/memory_manager.py` | 演化:单例入口改指 `MemoryService`;`get_memory_context` 标记废弃、内部改走 builder | 保留函数签名以免破坏导入 |
| `memory/memory_prompt_builder.py` | 保留 + 扩展 | `MEMORY_CATEGORIES` 补 `relationship`;`to_prompt` 支持恒注入块 |
| `memory/__init__.py` | 保留导出 + 新增 | 新增 `MemoryService`/`MemoryRepository` 等 |
| `core/conversation_runtime.py` | 扩展 | 历史改走 `ConversationStore`;注入 BondState render |
| `ui/character_conversation_runner.py` | 改造 | `_history` 内存 list → `ConversationStore` |
| `app.py` | 装配 | 初始化 conversation store / bond engine / memory service / memory panel |
| `character/*` | 不动 | 人格保持静态 |
| `core/session_manager.py` 等 | 不动 | 原生 session 与 Firefly 对话无关 |

### 8.3 新增文件清单(全新增,零删除)

| 文件 | 阶段 |
|------|------|
| `memory/records.py` `repository.py` `mem0_adapter.py` `service.py` `write_guards.py` | P1 |
| `core/conversation_store.py` `companion_config.py` | P0 |
| `core/bond_state.py` | P2 |
| `ui/memory_panel.py` | P0/P1 |
| `config/companion.json`(默认值模板) | P0 |
| `runtime/companion/`(conversation.json / relationship.json / memory_records.json 首次初始化) | P0/P1/P2 |

### 8.4 迁移步骤(施工顺序)

1. **P0 — 连续性:** 建 `conversation_store.py` + `companion_config.py`;`CharacterConversationRunner._history` 改走 store;`ConversationRuntime.build_messages` 历史来源切换。验收:重启续聊。
2. **P1 — 显式记忆:** 建 `records.py` / `repository.py` / `mem0_adapter.py`(取代 mem0_client)/ `write_guards.py` / `service.py`;`MEMORY_CATEGORIES` 补 `relationship`;同步更新受影响断言;接入显式"记住 X"触发。验收:显式记忆落库并后续引用。
3. **P1 — 权限:** 建 `memory_panel.py`;接 write_policy / 溯源 / 红线 / 否定。验收:可查看/删除/清空/导出。
4. **P2 — 关系:** 建 `bond_state.py`;接信号检测(轮次/感谢/约定);render 恒注入。验收:亲疏可观察不同。

### 8.5 风险与回滚

| 风险 | 缓解 |
|------|------|
| 新增 `relationship` 类别破坏现有断言 | 单独提交类别变更 + 测试同步,先跑全量回归再继续 |
| `memory_manager.py` 演化破坏导入 | 保留旧函数签名,内部转发;`get_memory_context` 标记 deprecated 但可用 |
| 双写(索引+向量)不一致 | 索引为真相源;`reconcile()` 兜底;向量写失败不阻断索引 |
| 迁移中丢失存量数据 | `runtime/` 下所有旧文件只读保留,新文件走新路径,不做原位覆盖 |

## 9. 施工顺序总览与 Definition of Done

```text
P0 连续性
  ├─ conversation_store.py + companion_config.py
  ├─ runner 历史切换
  └─ DoD: 重启后续聊;has_history 恢复

P1 显式记忆 + 权限
  ├─ records / repository / mem0_adapter / write_guards / service
  ├─ 类别补 relationship + 回归同步
  ├─ 显式"记住 X"触发 + memory_panel
  └─ DoD: 显式记忆落库引用;用户可查看/删除/清空/导出

P2 关系引擎
  ├─ bond_state.py + 信号检测 + render 恒注入
  └─ DoD: 亲疏可观察不同;注入无法改写状态
```

**全局 Definition of Done(任一阶段交付前必须满足):**

1. 新增模块 100% 有对应测试套件(T1–T12),全离线可跑。
2. 现有 27 套件回归全绿。
3. 隐私不变式通过断言:记忆提取/写入路径**零**远程 LLM 调用。
4. `memory/` 不 import `core/`/`ui/`;`core/` 不 import `ui/`;仅 `mem0_adapter.py` import `mem0`。
