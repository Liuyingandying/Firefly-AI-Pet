## 0. 输入数据特征（校准结论，先读）

基于 Stage 0.5 对真实豆包导出的分析，设计必须面对三个事实：

1. **格式已定**：`ParsedHistory` 为 JSON 数组导出，`Turn{role, content, ts, seq, message_id, content_type}`，`Role ∈ {user, bot}`。
2. **分布**：4371 轮 = user 2142 / bot 2229；`content_type` = text 4286 / block 80 / image 5。
3. **★ 内容是角色扮演（roleplay）**：assistant（bot）消息含大量舞台指示与括号动作，如 `（眼神中透露出一丝疯狂，紧紧盯着你）`、`*听到这个字，心里不禁揪紧*`；用户也在**代入角色**（如 `我说我好像喜欢上她了，真的。`）。

**角色扮演带来的两条硬约束：**

- **assistant 是旧人格角色**，绝非事实/风格/关系来源（本就不采信，这里更加铁）。
- **用户消息里"in-character 的话"不是用户真实事实**。`"我喜欢上她了"` 是角色台词，不能提取为 `user_fact: 用户喜欢某人`。→ 必须引入 **roleplay 置信度惩罚 + 人工确认**，否则会把角色扮演的虚构当真实记忆写入。

## 1. 候选数据模型

### 1.1 顶层 `MigrationCandidate`

```text
MigrationCandidate {
  run_id: str,                 # 幂等/回滚锚点
  source_file: str,
  source: "doubao",
  rule_version: int,
  generated_at: int,
  memory: [ MemoryCandidate ],
  bond:   [ BondCandidate ],
  style:  [ StyleCandidate ],
  stats:  { ... }              # 各 kind 的 total / auto_approve / needs_review / auto_reject
}
```

### 1.2 三个候选类型（kind 判别）

```text
MemoryCandidate {
  id: str, kind: "memory",
  category: MemoryCategory,     # user_fact/preference/project/shared_experience/emotion/relationship
  content: str,
  confidence: float(0..1), band: "high"|"medium"|"low"|"rejected",
  evidence: [ SourceRef ],      # §6
  rule: str,
  disposition: "auto_approve"|"needs_review"|"auto_reject",
  flags: [ str ]
}

BondCandidate {
  id: str, kind: "bond",
  signal_type: BondSignalType,  # 以 core/bond_rules.py 实际枚举为准
  detail: str | null,           # SHARED_MILESTONE/PROMISE_* 的标签/约定文本
  confidence, band, evidence, rule, disposition, flags
}

StyleCandidate {
  id: str, kind: "style",
  dimension: "nickname"|"tone"|"verbosity"|"boundary",
  content: str,                 # 归一化偏好文本
  confidence, band, evidence, rule, disposition, flags,
  review_only: true             # Style 永不自动改 yaml
}
```

### 1.3 来源引用 `SourceRef`（evidence 链的最小单元）

```text
SourceRef {
  conversation_id: str,
  turn_seq: int,                # 对应 ParsedHistory 里 Turn.seq（全局递增）
  role: "user" | "assistant",
  ts: str | null,
  message_id: str | null        # 直连豆包原始 message_id
}
```

## 2. user/assistant 归因规则（显式）

### 2.1 总则

| 来源 | 可否作为事实来源 | 可否作为风格来源 | 可否触发关系信号 | 允许的用途 |
|------|----------------|----------------|----------------|-----------|
| **user turn** | ✅ | ✅（仅显式偏好） | ✅ | 事实、偏好、情绪、项目、里程碑/约定的**标签与触发** |
| **assistant turn** | ❌ | ❌ | ❌（仅共指佐证） | 里程碑/约定的**共指佐证**、摘要素材、归档原文 |

### 2.2 逐条硬规则

- **R1（事实锚定）**：任何 `memory`/`style` 候选的 `evidence` **必须至少含一条 `role=user` 的 SourceRef**；否则 `band=rejected`、`flags += ["assistant_derived"]`。这条在模型层强制校验。
- **R2（assistant 转述不作数）**：assistant 说"你之前说过你是医生"不产生候选；必须找到**原始 user turn** 佐证，且 `evidence` 指向那条 user turn。
- **R3（里程碑标签归因）**：用户说"我们一起做完了"→ 信号成立；但**标签若只出现在 assistant turn**，则 `flags += ["assistant_derived"]`、`disposition=needs_review`、`confidence` 降档——标签由人工补全，不自动采用 assistant 措辞。
- **R4（TURN_COMPLETED 机械计数）**：由 user↔assistant 交换对计数产生，不依赖任何一方"说"了什么，无归因歧义。
- **R5（roleplay 归因）**：用户消息若被判定为 in-character（§4 的 `roleplay_penalty`），**默认不采信为 user_fact/emotion**，`disposition=needs_review`；仅显式 out-of-character（OOC）标记或明确的现实陈述（"现实里我是…"）才给高置信。

## 3. confidence 计算（显式、确定性）

### 3.1 Memory 候选置信度

```text
confidence = clamp(0, 1,
    base
  + explicit
  + repetition
  + specificity
  - hedging
  - roleplay_penalty
)
```

| 因子 | 值 | 触发条件 |
|------|----|---------|
| `base` | +0.4 | 来源为 user turn（assistant 来源 → 直接 rejected，不打分） |
| `explicit` | +0.3 | 含显式标记：`记住`/`我是`/`我喜欢`/`我的`/`我们一起`/`叫我` |
| `repetition` | +0.2（≥3 轮）/ +0.1（2 轮） | 同一事实在 ≥2 个**不同 user turn** 重复出现 |
| `specificity` | +0.1 | 含具体名词/数字/地名/技术栈 |
| `hedging` | −0.2 | 含 `可能`/`也许`/`大概`/`不确定`/`感觉` |
| `roleplay_penalty` | −0.3 | 来源会话被判定为 roleplay-heavy（§4.1）且无 OOC 标记 |
| `contradiction` | → 0 | 更晚的 user turn 与该事实冲突（较新者胜出），`flags += ["contradiction"]` |
| 红线（密钥/PII 无条件） | → 0 | `flags += ["red-line"]`，直接 `auto_reject` |

### 3.2 Bond 候选置信度（按信号类型，机械信号固定高）

| signal_type | 默认 confidence | 说明 |
|-------------|----------------|------|
| `TURN_COMPLETED` | 0.9 | 确定性计数 |
| `THANKED` / `CORRECTION` | 0.8（强关键词）/ 0.5（弱） | 关键词匹配强度 |
| `SHARED_MILESTONE` | 0.8（标签在 user）/ 0.4（标签在 assistant） | 归因规则 R3 |
| `PROMISE_MADE` | 0.6 | 约定文本抽取 |
| `PROMISE_KEPT` / `PROMISE_MISSED` | 0.6 | 需历史佐证 |

### 3.3 Style 候选置信度

| 条件 | confidence |
|------|-----------|
| 显式偏好（`叫我X`/`说话温柔点`/`回复短一点`） | 0.8 |
| 隐式/需推断 | 0.4 |

### 3.4 band → disposition 映射

| band | 区间 | 默认 disposition |
|------|------|------------------|
| high | ≥ 0.7 | `auto_approve`（仅安全类别） |
| medium | 0.4–0.7 | `needs_review` |
| low | 0.15–0.4 | `needs_review`（敏感）或 `auto_reject` |
| rejected | < 0.15 或 = 0 | `auto_reject` |

> 分诊是**默认值**，用户可覆盖任意候选（§7）。

## 4. roleplay 判定（本数据特有的横切机制）

### 4.1 会话级 roleplay 分数（确定性）

```text
roleplay_score(conversation) =
    count(assistant turns 含 stage-direction 标记) / count(assistant turns)
```

stage-direction 标记 = 括号 `（…）`、星号动作 `*…*`、`（` `）` 成对出现。阈值（默认 0.5）以上判定为 roleplay-heavy。

### 4.2 OOC 标记（提升置信）

用户 turn 含 `((` / `（(` / `ooc:` / `跳出角色` / `现实里` 等 → 视为 out-of-character，**豁免** `roleplay_penalty`。

## 5. 三个提取器（施工图）

### 5.1 MemoryExtractor

```text
MemoryExtractor.extract(ParsedHistory) -> [ MemoryCandidate ]
```

- **输入**：仅遍历 `role=user` 的 turn（归因 R1）。
- **规则集**（`rule_version` 版本化，确定性正则/关键词）：

| rule id | 触发 | category |
|---------|------|----------|
| `mem.user_fact.occupation` | `我是(一名)?(医生|老师|程序员|…)` | user_fact |
| `mem.user_fact.location` | `我在(.+)`/`住(.+)` | user_fact |
| `mem.user_fact.name` | `我叫(.+)` | user_fact |
| `mem.preference.nickname` | `叫我(.+)` | preference |
| `mem.preference.verbosity` | `(回复|说话)(短|长|简洁)一点` | preference |
| `mem.project.context` | `(我在|我们)(开发|做|写)(.+)` | project |
| `mem.emotion.state` | `我(最近)?(很|有点)(开心|难过|焦虑|累)` | emotion |
| `mem.experience.together` | `我们(一起)?(完成|做|经历)(了)?(.+)` | shared_experience |
| `mem.relationship.trust` | `我(很)?信任你` | relationship |

- **后处理**：红线过滤 → 去重合并（同 category 语义相似度 ≥ 0.85 合并）→ 矛盾消解（较新 user turn 胜出）。
- **产出**：`MemoryCandidate`（含 confidence、evidence、rule、disposition）。

### 5.2 BondExtractor

```text
BondExtractor.extract(ParsedHistory) -> [ BondCandidate ]
```

- **规则集**：

| rule id | 触发 | signal |
|---------|------|--------|
| `bond.turn` | 每个 user↔assistant 交换对（机械计数） | `TURN_COMPLETED`（经批量折扣，见迁移总设计 §6） |
| `bond.thank` | user 含 `谢谢|感谢|太好了|帮大忙` | `THANKED` |
| `bond.correction` | user 含 `不对|错了|应该是` | `CORRECTION` |
| `bond.milestone` | user 含 `我们一起(完成|达成|发布)(了)?(.+)` | `SHARED_MILESTONE(detail)` |
| `bond.promise` | user 含 `(下次|明天|以后)(我们|再|继续)(.+)` | `PROMISE_MADE(detail)` |
| `bond.promise_kept/missed` | 约定后续被 user 佐证兑现/未兑现 | `PROMISE_KEPT/MISSED(detail)` |

- **归因**：信号触发只认 user turn；assistant turn 仅用于 R3 共指佐证。
- **产出**：`BondCandidate`（`detail` 为标签/约定文本）。

### 5.3 StyleExtractor

```text
StyleExtractor.extract(ParsedHistory) -> [ StyleCandidate ]
```

- **输入**：仅 user turn（归因 R1）。
- **规则集**：

| rule id | 触发 | dimension |
|---------|------|-----------|
| `style.nickname` | `叫我(.+)` | nickname |
| `style.tone` | `(说话|语气)(温柔|直接|轻松|撒娇)一点` | tone |
| `style.verbosity` | `(回复|回答)(短|长|简洁)一点` | verbosity |
| `style.boundary` | `(不用|别)每次都(.+)` | boundary |

- **产出**：`StyleCandidate`（`review_only=true`；落地为 `preference` 记忆 + 只读 report，**永不改 yaml**）。

---

## 6. evidence 链（保留）

- 每个候选 `evidence: [ SourceRef ]` **非空**，`SourceRef` 直连 `conversation_id + turn_seq + message_id`。
- 完整链：`CandidateItem.rule → CandidateItem.evidence → ParsedHistory.turn(seq) → 豆包 message_id`。
- **丢弃日志**：`MigrationCandidate.stats` 之外，另产 `discard_log`（`{rule, reason, evidence}`），回答"为什么没进"。
- 幂等：同一 `run_id + source_sha256` 重跑 → 相同候选与相同 `id`。

## 7. migration_preview 格式（人工确认面）

```json
{
  "run_id": "mig-20260825-001",
  "source": "doubao",
  "source_file": "conversations.txt",
  "rule_version": 1,
  "summary": {
    "memory": {"total": 12, "auto_approve": 5, "needs_review": 6, "auto_reject": 1},
    "bond":   {"total": 8,  "auto_approve": 6, "needs_review": 2, "auto_reject": 0},
    "style":  {"total": 2,  "auto_approve": 0, "needs_review": 2, "auto_reject": 0}
  },
  "groups": {
    "memory": [
      {
        "id": "m-0001",
        "category": "user_fact",
        "content": "用户是后端开发",
        "confidence": 0.8,
        "band": "high",
        "disposition": "auto_approve",
        "flags": [],
        "rule": "mem.user_fact.occupation",
        "evidence": [
          {"conversation_id": "c1", "turn_seq": 0, "role": "user",
           "ts": "2024-10-29T12:09:29Z", "message_id": "241173238154754"}
        ],
        "preview": "你在 2024-10-29 说：「我是后端开发」"
      }
    ],
    "bond": [],
    "style": []
  }
}
```

- `preview` 是给人看的渲染文本（"你在 <ts> 说：「<原文片段>」"）。
- 确认操作：`accept` / `edit`（改 content 或 detail 后确认）/ `reject` / 按类别或 run_id 批量拒。
- 分诊默认值可覆盖；`style` 组一律标 `review_only` 警示。

## 8. 数据流与示例

```text
ParsedHistory (34 conv / 4371 turn)
  → MemoryExtractor.extract → [ MemoryCandidate ]
  → BondExtractor.extract   → [ BondCandidate ]
  → StyleExtractor.extract  → [ StyleCandidate ]
  → 聚合 + 分诊 → MigrationCandidate → migration_preview → (人工确认) → Stage 2 Commit
```

### 8.1 示例（基于真实数据）

输入（conv `c1`）：

```text
seq0 assistant: （眼神中透露出一丝疯狂，紧紧盯着你）空，你今天去哪了？
seq1 user:      我说我好像喜欢上她了，真的。
seq2 assistant: 她？（*听到这个字，心里不禁揪紧*）是谁？
```

产出：

| 候选 | 判定 | 依据 |
|------|------|------|
| `user_fact: 用户喜欢某人` | **不产生 / rejected** | seq1 是 in-character 角色台词（roleplay_penalty），R5 |
| `bond.turn` ×1 | auto_approve | user↔assistant 交换对（机械） |
| 其它 | 无 | 无显式事实/偏好/里程碑/约定 |

反例说明：若把 seq1 提取为"用户喜欢某人"，即把角色扮演的虚构写进长期记忆——这正是 `roleplay_penalty` 要拦的。

## 9. 施工图：模块边界与方法契约

| 模块 | 职责 | 输入 | 输出 | 依赖 |
|------|------|------|------|------|
| `candidates.py` | 候选数据模型 + SourceRef | — | 类型 | 仅 `memory.records`（枚举）、`core.bond_rules`（枚举） |
| `confidence.py` | §3 的确定性打分 + band/disposition | 候选原始字段 | 打分后的候选 | 纯函数 |
| `attribution.py` | §2 归因校验（R1–R5）+ roleplay 判定 | turn/候选 | 校验结果 | 纯函数 |
| `memory_extractor.py` | §5.1 | ParsedHistory | [MemoryCandidate] | 规则表 |
| `bond_extractor.py` | §5.2 | ParsedHistory | [BondCandidate] | 规则表 |
| `style_extractor.py` | §5.3 | ParsedHistory | [StyleCandidate] | 规则表 |
| `preview.py` | §7 渲染 migration_preview | MigrationCandidate | JSON | 纯函数 |

**边界**：这些模块**零写入、零远程 LLM、零 Qt**；只读 `ParsedHistory`，只产出候选。`candidates.py` 可 import `memory.records`（只取枚举）与 `core.bond_rules`（只取枚举），但**不得 import 任何会写库的模块**。

### 9.1 测试矩阵

| # | 套件 | 关键用例 |
|---|------|---------|
| E1 | 归因 | R1 强制 user evidence；R2 assistant 转述不产生；R3 标签归因降档；R5 roleplay 拦截 |
| E2 | 置信度 | 各因子加减；矛盾归零；红线归零；band 阈值边界 |
| E3 | MemoryExtractor | 每类规则命中；去重合并；矛盾取新 |
| E4 | BondExtractor | 各信号；机械计数折扣；标签归因 |
| E5 | StyleExtractor | 显式偏好；review_only 恒真 |
| E6 | preview | 分组/排序/`preview` 渲染/evidence 非空 |
| E7 | 幂等/evidence | 同输入同输出；evidence 链可回溯到 message_id |
| E8 | 回归 | 现有 27+ 套件 + Stage 0 测试全绿 |

## 10. 风险与开放问题

| 风险 / 开放问题 | 缓解 / 待决 |
|----------------|------------|
| roleplay 判定（IC/OOC）准确率 | 确定性标记 + `roleplay_penalty` + 人工确认兜底；默认保守 |
| 规则关键词召回/误报 | 规则版本化 + 置信度 + 人工确认 |
| 里程碑/约定标签抽取质量 | R3 归因 + 人工 edit detail |
| `MemorySource` 是否新增 `migrated` | 建议新增；否则回退 `suggested + trigger=migration:*` |
| `relationship` 类与 Bond 双真相 | 迁移尽量不产出 relationship MemoryRecord；数值/约定只走 Bond |
