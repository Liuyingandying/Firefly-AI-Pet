# Firefly AI Pet v0.3 HistoryAnalyzer 工程设计

**文档性质:** 工程设计文档（design-only，不含实现代码；所有接口以"方法契约"描述）
**版本:** v0.3-migration-stage1
**日期:** 2026-08-25
**前置:** `docs/engineering/v0.3_history_migration_design.md`（迁移总设计）、Stage 0 `tools/firefly_memory_importer/`（Parser）
**输入:** `ParsedHistory`（Stage 0 产物）
**输出:** `MigrationCandidate`（候选集，**只读、可审、未提交**）
**约束:** 隐私铁律（分析/检测**零远程 LLM**）；关系状态归系统引擎；Character/Memory/Bond 边界不变。

---

## 0. 定位与边界

`HistoryAnalyzer` 是迁移流水线的 **Stage 1**：把已归一化的 `ParsedHistory` 转成一份**候选集**，供人工确认后，由**Stage 2（Commit，本文档不涉及）**通过既有受信通道写入。

```text
Stage 0  Parser        conversations.txt → ParsedHistory
Stage 1  HistoryAnalyzer  ParsedHistory → MigrationCandidate   ★ 本文档
Stage 2  Commit         MigrationCandidate → MemoryRecord / BondState / ConversationStore
```

**关键边界（必须写死）：**

- `HistoryAnalyzer` **只读、零写入**。它不碰 `memory_records.json` / `bond_state.json` / `conversation.json`，也不碰 `character/*.yaml`。
- 它**只产出候选**，候选的"落地"发生在 Stage 2，且必须经人工确认。
- 候选集**不可变、可重放**：同一 `ParsedHistory` + 同一规则版本 → 同一候选集（幂等）。

## 1. 核心数据模型

### 1.1 顶层容器 `MigrationCandidate`

```text
MigrationCandidate {
  run_id: str,                 # 本次分析批次的唯一标识（幂等/回滚的锚点）
  rule_version: int,           # 提取规则集版本号（规则变更即失效旧候选）
  source_file: str,            # 对应 ParsedHistory.source_file
  source_sha256: str,          # 输入指纹
  generated_at: int,
  items: [ CandidateItem ],
  stats: {                     # 便于 UI 展示与人工审核
    by_kind: { memory, bond, style },
    by_disposition: { auto_approve, needs_review, auto_reject }
  }
}
```

### 1.2 候选条目 `CandidateItem`（按 `kind` 判别）

```text
CandidateItem {
  id: str,                     # 稳定、可排序
  kind: "memory" | "bond" | "style",

  # kind-specific（三者取其一，其余为 null）
  category: MemoryCategory | null,        # memory 专用
  signal_type: BondSignalType | null,     # bond 专用
  style_dimension: str | null,            # style 专用（称呼/语气/长度/边界…）

  content: str,                # 归一化文本（memory/style 的内容；bond 的 detail）
  confidence: float(0..1),     # 确定性打分（§5）
  band: "high" | "medium" | "low" | "rejected",

  evidence: [ SourceRef ],     # 来源追踪（§6）
  rule: str,                   # 产出该候选的规则 id（审计）
  disposition: "auto_approve" | "needs_review" | "auto_reject",  # §7
  flags: [ str ]               # red-line / assistant_derived / contradiction / pii / hedged
}
```

### 1.3 来源引用 `SourceRef`

```text
SourceRef {
  conversation_id: str,
  turn_seq: int,               # 对应 Stage 0 Turn.seq（全局递增，顺序可回溯）
  role: "user" | "assistant",
  ts: str | null
}
```

**原则：一个候选可有多个 evidence（重复出现即多证据），但每个证据必须能定位到具体 turn。**

## 2. 三类候选的区分与落地

| 维度 | Memory | Bond | Style |
|------|--------|------|-------|
| 语义 | "我记得什么" | "我们经历了什么" | "你希望我怎么表达" |
| 内容来源 | **仅用户 turn**（§4） | 用户 turn + assistant 共指佐证 | **仅用户 turn 的显式偏好** |
| 目标落地 | `MemoryRecord`（6 类） | `BondSignal` → `BondStateEngine` 重放 | `preference` MemoryRecord + 只读 style_report |
| 是否触碰 character/*.yaml | 否 | 否 | **否（永不自动改）** |
| 是否需要置信度 | 是 | 是（机械信号高、语义信号低） | 是（仅显式偏好高） |

### 2.1 Memory 候选 → 类别映射

| 检测内容（用户消息） | category |
|---------------------|----------|
| 稳定事实（职业/城市/技术栈/姓名/称呼） | `user_fact` |
| 对语气/称呼/长度的偏好 | `preference` |
| 项目/技术决策、进度 | `project` |
| 情绪高光（"我最近很焦虑"） | `emotion` |
| "我们一起完成/经历 X" 的**叙事** | `shared_experience` |
| 关系表述（"我信任你"） | `relationship`（低频，数值真相仍在 Bond） |

> `relationship` 类 MemoryRecord 与 BondState 的边界：数值/约定/里程碑归 Bond；`relationship` 类只保存**定性的关系事实文本**，且迁移中尽量不产出（避免双真相源）。

### 2.2 Bond 候选 → 信号映射（以 `core/bond_rules.py` 实际枚举为准）

| 检测（用户 turn 为主） | signal_type | detail |
|----------------------|-------------|--------|
| 一轮有效交流（确定性计数） | `TURN_COMPLETED` | — |
| 感谢/认可（关键词） | `THANKED` | — |
| 纠正流萤（关键词） | `CORRECTION` | — |
| "我们一起完成/达成 X" | `SHARED_MILESTONE` | 里程碑**标签** |
| "下次/明天…"约定 | `PROMISE_MADE` | 约定文本 |
| 约定兑现/未兑现（历史佐证） | `PROMISE_KEPT` / `PROMISE_MISSED` | 约定文本 |

### 2.3 Style 候选 → 维度

| 维度 | 示例 |
|------|------|
| 称呼（nickname） | "叫我小萤" |
| 语气（tone） | "你说话温柔点" / "别那么客气" |
| 长度（verbosity） | "回复短一点" |
| 边界（boundary） | "不用每次都问我在不在" |

Style 候选**只来自显式偏好句**；它落地为 `preference` MemoryRecord（运行时注入，塑造表达），并额外生成一条**只读** style_report 建议供人工审，**绝不自动改 yaml**。

## 3. 提取规则（确定性，零 LLM）

所有提取走**确定性规则**（关键词/正则/结构计数），默认不调用任何 LLM；可选本地分类器作为质量增强（默认关闭，见 §9）。

### 3.1 Memory 提取规则（示例）

| rule id | 触发 | 抽取 | 类别 |
|---------|------|------|------|
| `mem.user_fact.occupation` | `我是(一名)?(医生|老师|程序员…)` | 职业 | user_fact |
| `mem.user_fact.location` | `我在(城市)` / `住(城市)` | 城市 | user_fact |
| `mem.preference.nickname` | `(叫我|称呼我)(为)?(.+)` | 昵称 | preference |
| `mem.preference.verbosity` | `(回复|说话)(短一点|长一点|简洁)` | 长度偏好 | preference |
| `mem.project.context` | `(我在|我们)(开发|做|写)(.+项目)` | 项目 | project |
| `mem.emotion.state` | `我(最近)?(很|有点)(开心|难过|焦虑|累)` | 情绪 | emotion |
| `mem.experience.together` | `我们(一起)?(完成|做了|经历)(了)?(.+)` | 叙事 | shared_experience |
| `mem.relationship.trust` | `我(很)?信任你` | 关系事实 | relationship |

### 3.2 Bond 提取规则（示例）

| rule id | 触发 | signal |
|---------|------|--------|
| `bond.turn` | 每个有效 user↔assistant 交换 | `TURN_COMPLETED`（经批量折扣，见迁移总设计 §6） |
| `bond.thank` | `谢谢|感谢|太好了|帮大忙` | `THANKED` |
| `bond.correction` | `不对|错了|应该是|不是这样` | `CORRECTION` |
| `bond.milestone` | `我们一起(完成|达成|发布)(了)?(.+)` | `SHARED_MILESTONE(detail)` |
| `bond.promise` | `(下次|明天|以后)(我们|再|继续)(.+)` | `PROMISE_MADE(detail)` |

### 3.3 Style 提取规则

| rule id | 触发 | 维度 |
|---------|------|------|
| `style.nickname` | `叫我(.+)` | 称呼 |
| `style.tone` | `(说话|语气)(温柔|直接|轻松)一点` | 语气 |
| `style.verbosity` | `(回复|回答)(短|长|简洁)一点` | 长度 |

**规则集带版本号（`rule_version`）**：任何规则增删改都要 bump 版本，旧候选因此失效并提示重新分析——这是"可重放 + 可审计"的保证。

## 4. 防止 assistant 污染事实（硬规则）

这是 HistoryAnalyzer 最重要的安全约束。**旧流萤的回复（assistant turn）不是事实，也不是人格。** 若不加隔离，会把旧人格（可能含"AI 宠物/助手"自我定位）与旧模型编造的内容回流进记忆与人格。

### 4.1 assistant turn 的用途白名单

| 用途 | 允许 | 说明 |
|------|------|------|
| 作为**用户事实**的来源 | ❌ | 旧流萤转述的"你做过 X"不是地面真相 |
| 作为**风格/人格**的来源 | ❌ | 旧人格永不回流 |
| 作为**关系数值**的来源 | ❌ | 只有用户消息触发 bond 信号 |
| 作为**里程碑/约定的共指佐证** | ✅（受限） | 只用于确认"确实共同完成/约定"，**标签文本仍取自用户 turn**（§4.2） |
| 作为**摘要素材** | ✅（受限） | 只统计话题/轮数/时长，不复制语气 |
| 作为**归档原文** | ✅ | 原样进入 Stage 2 的归档，不做提炼 |

### 4.2 里程碑/约定标签的"归因"规则

当用户说"我们做完了"，assistant 说"我们完成了 X 项目"时：

- 里程碑**被检测到**（用户 turn 有"一起做完"）→ 信号成立。
- 但**标签 "X 项目" 若只出现在 assistant turn**，则：
  - 该候选 `flags += ["assistant_derived"]`；
  - `confidence` 降档（至少降为 medium）；
  - `disposition = needs_review`（**标签由人工补全或确认，不自动采用 assistant 的措辞**）。

**一句话：assistant 可以佐证"发生过"，但不能提供"事实内容"与"关系标签"。**

### 4.3 事实必须锚定在用户 turn

任何 `memory` / `style` 候选的 `evidence` 中**必须至少含一条 `role=user` 的 SourceRef**；否则该候选 `band = rejected`、`flags += ["assistant_derived"]`。这条在模型层可被强制校验。

## 5. 置信度模型（确定性、可解释）

置信度由**确定性因子**累加/扣减，不靠模型判断；输出一个 `float(0..1)` + 一个 `band`。

### 5.1 因子表

| 因子 | 影响 | 说明 |
|------|------|------|
| 来源为用户 turn | +0.4 | assistant 来源的事实置信度为 0（见 §4） |
| 显式标记（"记住/我是/我喜欢/我们一起"） | +0.3 | 意图明确 |
| 重复（≥2 个不同用户 turn 佐证） | +0.2 | 越重复越可信 |
| 具体性（含具体名词/数字/地点） | +0.1 | 可验证 |
| 模糊/不确定（"可能/也许/大概"） | −0.2 | 降低 |
| 与更晚用户 turn 冲突 | → 0 | 较新用户消息胜出，旧候选 `flags += ["contradiction"]` |
| 命中红线（密钥/PII 无条件） | → 0 | `flags += ["red-line"]`，直接 `auto_reject` |

### 5.2 band 映射

| 区间 | band | 默认 disposition |
|------|------|------------------|
| ≥ 0.7 | high | auto_approve（仅限安全类别） |
| 0.4–0.7 | medium | needs_review |
| < 0.4 | low | needs_review（敏感）或 auto_reject |
| 0 | rejected | auto_reject |

**机械信号例外：** `bond.turn`（轮次计数）与 `bond.thank`（关键词强匹配）置信度固定为 high；`bond.milestone`/`bond.promise` 因涉及**标签抽取**，置信度按 §4.2 归因规则下调。

## 6. 来源追踪（Provenance）

- 每个候选的 `evidence: [ SourceRef ]` **不可为空**，且每条引用可定位到 `conversation_id + turn_seq`。
- 候选的 `rule` 字段记录**是哪条规则**产出的，用于审计"这条记忆/信号为什么被提取"。
- 丢弃的候选也保留在审计侧（`MigrationCandidate.stats` + 丢弃原因），回答"为什么没进"。

**审计链：** `CandidateItem.rule → evidence → ParsedHistory.turn` 完整可回溯。这是 Stage 2 落地后"为什么 trust=0.4 / 为什么有这条记忆"的可解释基础。

## 7. 人工确认机制

候选**默认不落地**，进入一个**三态分诊**：

| disposition | 触发条件 | 用户操作 |
|-------------|---------|---------|
| `auto_approve` | high 置信度 且 安全类别（user_fact/preference/project 等） 且 无 flags | 可批量确认，或逐个撤销 |
| `needs_review` | medium 置信度，或敏感（emotion/relationship/PII/assistant_derived），或 bond 语义信号 | **必须逐条确认/编辑/拒绝** |
| `auto_reject` | red-line、assistant 派生事实、contradiction、low 且非敏感 | 默认排除，可人工恢复 |

**分诊只是默认值，用户可对任意候选覆盖。**

### 7.1 确认操作（用户主权）

- **确认（accept）** — 标记为可落地。
- **编辑（edit）** — 改 `content` / 标签后确认（尤其 bond 里程碑标签、emotion 措辞）。
- **拒绝（reject）** — 排除该候选。
- **一键全拒 / 按类别拒 / 按 run_id 拒** — 逃生门。

### 7.2 呈现与粒度

- 按 `kind` 分组（Memory / Bond / Style），每类内部按 `band` 降序。
- 每条候选展示：`content` + `confidence` + `evidence` 摘要（哪几轮、哪方说的）+ `rule` + `flags`。
- `style` 候选额外展示"建议但**不自动改 yaml**"的警示。

## 8. 可回滚

`HistoryAnalyzer` 本身不写库，因此它的"回滚"是**提交前**的：候选集不可变、未提交，丢弃/拒绝即回滚。为支撑 Stage 2 的**提交后**回滚，候选模型必须满足：

1. **`run_id` 贯穿** — 每个候选携带 `run_id`；Stage 2 落地时把 `run_id` 写进 `MemoryRecord.trigger`（`migration:<run_id>`）与迁移审计，从而可**按 run_id 精确删除**本次全部产物。
2. **幂等** — 同一 `run_id` + 同一 `source_sha256` 重复分析 → 相同候选；重复提交 → no-op（去重合并，绝不重复新增）。
3. **不可变** — 候选集一旦生成即为快照；编辑/确认产生的是**确认层记录**，不改写原候选（可 diff、可撤销）。
4. **规则版本化** — `rule_version` 变更 → 旧候选失效并强制重新分析，避免"旧规则产物"被误用。

**回滚动作（Stage 2 执行，本文档只定义契约）：**
- 恢复 `memory_records.json / bond_state.json / conversation.json` 的迁移前快照；
- 或按 `source=migrated & trigger=migration:<run_id>` 定向删除；
- Bond 可通过既有 `BondStateEngine.reset()` 归零。

## 9. 完整数据流与示例

```text
ParsedHistory
  → (遍历 turn，逐条跑规则) 抽取原始发现
  → (assistant 隔离 + 红线 + 归因) 过滤/降档
  → (置信度打分 + 去重合并) 归一为 CandidateItem
  → (分诊) 打 disposition
  → 聚合为 MigrationCandidate（含 stats + run_id）
```

### 9.1 示例

输入（Stage 0 已解析，`seq` 全局递增）：

```text
conv#1
  seq0 user:   我在杭州做后端开发
  seq1 assistant: 原来你在杭州呀，后端开发很厉害！
  seq2 user:   我们一起完成了 Firefly v0.3 的迁移设计
  seq3 assistant: 对呀，我们完成了迁移设计！   ← 标签佐证，但"迁移设计"四字用户已说过
  seq4 user:   谢谢你，帮了大忙
```

输出候选：

| id | kind | 内容 | confidence | band | evidence | disposition |
|----|------|------|-----------|------|----------|-------------|
| c1 | memory | `user_fact`：用户是杭州后端开发 | 0.8 | high | seq0(user) | auto_approve |
| c2 | bond | `SHARED_MILESTONE`：完成 Firefly v0.3 迁移设计 | 0.7 | high | seq2(user) + seq3(assistant 佐证) | auto_approve |
| c3 | bond | `THANKED` | 0.9 | high | seq4(user) | auto_approve |
| c4 | bond | `TURN_COMPLETED` ×N | 0.9 | high | 计数 | auto_approve |

反例（assistant 污染被拦截）：若 seq1 里 assistant 说"你之前说过你想转行做产品"（用户从未说过），这条**不产生** `user_fact` 候选；若强行产生则 `band=rejected, flags=["assistant_derived"]`。

## 10. 验收标准与测试矩阵

| # | 套件 | 覆盖 | 关键用例 |
|---|------|------|---------|
| A1 | 规则提取 | Memory/Bond/Style 规则 | 每类样例 → 正确 kind/category/signal |
| A2 | assistant 隔离 | §4 | assistant 转述不成事实；里程碑标签归因降档；assistant 文本不进 style |
| A3 | 置信度 | §5 | 重复提权、模糊降权、矛盾归零、红线归零 |
| A4 | 来源追踪 | §6 | 每个候选 evidence 非空且可定位；rule 可审计 |
| A5 | 分诊 | §7 | high 自动过、medium 需审、red-line 自动拒 |
| A6 | 幂等/可回滚 | §8 | 同输入同输出；run_id 贯穿；规则版本变更失效旧候选 |
| A7 | 回归 | 全量 | 现有 27+ 套件全绿；Stage 0 测试不受影响 |

**DoD：**
1. 分析全程**零远程 LLM**（可静态审计）。
2. 任何 `memory`/`style` 候选的 evidence 必含 `role=user`。
3. 任何候选可溯源到 `rule + evidence`，任何丢弃可溯源到原因。
4. 候选集幂等、不可变、带 `run_id`，可被 Stage 2 精确落地与回滚。
5. `character/*.yaml` 在分析阶段**零改动**。

## 11. 风险与开放问题

| 风险 / 开放问题 | 缓解 / 待决 |
|----------------|------------|
| 规则关键词召回/误报 | 规则集版本化 + 置信度 + 人工确认兜底 |
| 语义抽取（里程碑标签/情绪）准确率 | 标签归因规则（§4.2）+ 人工编辑；可选**本地**分类器（默认关，永不远程） |
| `relationship` 类与 Bond 双真相 | 迁移尽量不产出 relationship MemoryRecord；数值/约定只走 Bond |
| `MemorySource` 是否新增 `migrated` | 建议新增（审计清晰）；否则回退 `suggested + trigger=migration:*` |
| 海量历史分析性能 | 规则为线性扫描；分批次（按 conversation 分片）处理 |
| Style 建议与 Character 边界的张力 | Style 只落 `preference` 记忆 + 只读报告，yaml 永不自动改 |
