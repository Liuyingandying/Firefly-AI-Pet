# Firefly AI Pet v0.3 历史聊天迁移工程设计

**文档性质:** 工程设计文档（design-only，不含实现代码）
**版本:** v0.3-migration
**日期:** 2026-08-25
**前置文档:** `docs/design/v0.3_companion_product_spec.md`、`docs/engineering/v0.3_engineering_implementation_design.md`、`docs/memory_architecture_review.md`
**输入:** 豆包（Doubao）导出的流萤聊天记录
**约束:** 本文档只做设计；隐私铁律（记忆提取/写入路径**零**远程 LLM）；关系状态归系统引擎独占写入。

---

## 0. 目标与四个产物

把一段历史对话转化为四个可落地、**不破坏 v0.3 安全不变式**的产物：

| # | 产物 | 落地位置 | 是否自动写入 |
|---|------|---------|-------------|
| 1 | Character Style | `preference` 记忆 + 只读 style report | 记忆自动；`character/*.yaml` **不自动** |
| 2 | MemoryRecord | `runtime/companion/memory_records.json` | 自动（经 `MemoryService`） |
| 3 | Shared Experience | `shared_experience` 记忆 + `BondState.shared_milestones` + 对话摘要 | 自动 |
| 4 | Bond Initialization | `runtime/companion/bond_state.json` | 自动（经 `BondStateEngine` 信号重放） |

**三条贯穿决策：**

1. **历史只产出"事实"与"信号"，绝不产出数值或 Prompt。** 迁移永远不直接写 `trust_level`/`phase`，也永远不直接改 `character/*.yaml`。
2. **人格（yaml）与关系数值都是系统资产。** 迁移只能通过既有引擎/服务写入（`MemoryService`、`BondStateEngine`、`ConversationStore`），绕过即违规。
3. **迁移必须可预览、可回滚、可审计、可重置。**

### 0.1 现状核对（实现 vs 设计文档漂移，必须先读）

工程实现设计文档（`v0.3_engineering_implementation_design.md`）与当前代码在**两处**存在漂移。迁移设计**以代码为准**，否则会写出不存在的字段：

| 维度 | 设计文档 §6.2 / §5.2 | **实际代码（真相）** |
|------|----------------------|---------------------|
| 关系状态字段 | `intimacy / trust / familiarity / interaction_count / first_met_ts / last_interaction_ts` | `BondState{ phase, trust_level, familiarity_level, shared_milestones, pending_promises }`（`core/bond_state.py`） |
| 关系信号 | `THANKED / SELF_DISCLOSURE / TAUGHT_FIREFLY / CORRECTION / PROMISE_*` | `BondSignalType{ TURN_COMPLETED, THANKED, CORRECTION, SHARED_MILESTONE, PROMISE_MADE, PROMISE_KEPT, PROMISE_MISSED }`（`core/bond_rules.py`） |
| 阶段分数 | `0.5·intimacy + 0.3·trust + 0.2·familiarity` | `score = (trust_level + familiarity_level) / 2`（`phase_for`） |
| 对话存储 | `turns + archive + summary`（双层） | `sessions[id] = { turns(有界≤40), summary }`，**无 archive 字段**（`core/conversation_store.py`） |

**对迁移的三条直接后果：**

- **Bond 初始化**只能落在实际 5 个字段上；`intimacy` 不是真实字段，"亲密度"由 `trust_level + familiarity_level + phase` 表达。
- **历史全文无法放进 `ConversationStore`**（无 archive）。全文另存于迁移专用归档文件，运行态只灌入"最近 K 轮工作窗口 + 摘要"。
- 信号重放必须使用实际枚举与增量（见 §6）。

## 1. 输入归一化

### 1.1 豆包导出格式假设

豆包导出常见为纯文本（`用户:` / `豆包:` 交替带时间戳）、JSON 消息数组或 HTML。**确切格式需用真实导出样本确认**（见 §11 开放问题）。迁移器对格式不敏感，靠一个薄的**解析适配层**把任意格式归一化为规范结构：

```text
ImportedTurn {
  role: "user" | "assistant",
  content: str,          # 原始文本，strip 后非空
  ts: int (ms),          # 缺失时按顺序递增推断（保持稳定）
  seq: int               # 原始顺序，用于审计溯源
}
ImportedSession {
  provider: "doubao",
  source_file: str,
  sha256: str,           # 输入指纹，用于幂等
  exported_at: int | null,
  turns: [ ImportedTurn ]
}
```

### 1.2 解析适配层

- 每类格式一个解析器，产出统一 `ImportedSession`。
- 缺时间戳时用 `seq` 递增补 `ts`，保证可排序；但**审计必须记录"时间戳是推断的"**，避免把推断时间当事实。
- 角色无法判定（如单列文本）→ 判为 `assistant` 前一轮无 `user` 时降级为"不可分类"，进入人工队列而非自动写入。

## 2. 总体流水线

```text
Stage 0  解析           Doubao 导出 → ImportedSession
Stage 1  过滤/消毒       红线、噪声、矛盾消解、旧人格隔离（§4）
Stage 2  分类            → facts / preferences / experiences / relational signals（§3）
Stage 3  推导 BondSeed   → 确定性计数 + 信号检测（§6）
Stage 4  重放与写入       BondStateEngine.apply 重放；MemoryService 导入；ConversationStore 摘要（§7）
Stage 5  审核与提交       人工审 style report；原子提交；幂等/回滚（§9）
```

每阶段：**输入 → 输出 → 守卫**，任何守卫失败即停在该阶段，不进入下游写入。

## 3. 数据分类规则

分类是**确定性规则**（关键词/结构），默认不调用任何 LLM；可选本地分类器作为质量增强（见 §11），但**绝不远程**。

### 3.1 分类决策表（消息内容 → 类别 → 落地）

| 检测到的内容 | MemoryCategory | 落地目标 | 是否进 Bond |
|-------------|----------------|---------|------------|
| 用户稳定事实（职业/城市/技术栈/称呼/名字） | `user_fact` | MemoryRecord | 否 |
| 用户对语气/称呼/回复长度的偏好 | `preference` | MemoryRecord | 否 |
| 项目/技术决策、进度 | `project` | MemoryRecord | 否 |
| 用户情绪高光（"我最近很焦虑"） | `emotion` | MemoryRecord | 否 |
| "我们一起做了 X" / 里程碑叙事 | `shared_experience` | MemoryRecord（叙事） | 是（只取**标签**进 `shared_milestones`） |
| 感谢 / 纠正 / 约定 / 信任表述 | —（不落 MemoryRecord） | BondSignal | 是（信号重放） |

**关键区分（防重复写）：**

- **里程碑**一分为二：**标签**（如 `完成 Firefly v0.3`）→ `BondState.shared_milestones`；**叙事**（如 `2026-08-25 我们一起完成了 v0.3 的 bond 引擎`）→ `shared_experience` MemoryRecord。两者不互相替代。
- **约定**只进 `BondState.pending_promises`（结构化、可 keep/missed），不单独写 `relationship` MemoryRecord。
- **`relationship` 类 MemoryRecord 在迁移中尽量不产出**：关系数值的真相在 BondState，历史里"信任/约定"应转成信号而非重复存文本，避免双真相源。

### 3.2 分类推断优先级（冲突时）

```
explicit 信号（感谢/约定/里程碑关键词） > preference（"我喜欢你叫我X"） > user_fact（稳定事实）
> project（技术） > emotion（情绪） > 丢弃（无法归类且无信息量）
```

### 3.3 走 Bond 的"关系信号"检测（确定性，同线上检测器）

复用 `core/bond_rules.py` 的信号语义，检测器只认**用户**消息（防污染，见 §5）：

| 历史观测 | 产出信号 | 说明 |
|---------|---------|------|
| 一轮有效交流 | `TURN_COMPLETED` | 需经"批量折扣"（§6.3） |
| 用户表达感谢/认可 | `THANKED` | 关键词（谢谢/感谢/太好了…） |
| 用户纠正流萤 | `CORRECTION` | 关键词（不对/错了/应该是…） |
| 共同里程碑（"我们一起完成/达成 X"） | `SHARED_MILESTONE(detail)` | 关键词 + 抽取标签 |
| 流萤应下约定（"下次/明天…"） | `PROMISE_MADE(detail)` | 关键词 + 抽取约定文本 |
| 约定已兑现/未兑现 | `PROMISE_KEPT/MISSED(detail)` | 需历史后续佐证 |

## 4. 信息过滤规则

过滤是**顺序管道**，前一级的输出是后一级的输入：

1. **红线过滤（永不通过，最高优先级）** — API key / token / 密码 / 身份证 / 手机号。复用 `memory_architecture_review.md` 的密钥模式正则；命中即整条丢弃并计数进审计。
2. **旧人格隔离（防污染核心，见 §5）** — assistant 消息不进入事实/风格/关系信号提取，仅用于（a）里程碑/约定的**共指佐证**、（b）对话摘要与归档原文。
3. **噪声过滤** — 丢弃纯问候、纯表情、"好的/嗯"、无信息量短句、系统提示/时间戳噪音。
4. **否定/废弃** — 历史后续出现"不要记住 X / 忘掉 X / 其实不是 X"时，丢弃或反转对应事实（以时间戳较新者为准）。
5. **矛盾消解** — 同一事实用户前后说法不一致时，**较新用户消息胜出**（时间序），旧版本不写入。
6. **PII 条件** — PII 仅当是**用户关于自己的自我披露**（非第三方、非他人隐私）才保留；否则丢弃。
7. **去重合并** — 写入前向量检索 top-1 相似项，相似度 ≥ 阈值（沿用 `dedup_similarity_threshold: 0.85`）则合并更新，不新增。
8. **长度/质量下限** — 每条候选记忆内容需 ≥ 阈值（如 4 字），否则并入相邻轮或丢弃。

**每级过滤都产出"丢弃原因"计数**，写进审计文件，回答"为什么这条没进记忆"。

## 5. 防止人格污染

**问题本质：** 历史里流萤的回复是**旧人格**的产物（很可能含"我是 AI 宠物/桌宠/助手"这类已被 v0.3 废弃的自我定位）。若迁移自动从 assistant 文本提炼风格并写回 `character/*.yaml`，会**回退**刚完成的 Character Layer 重定位。

### 5.1 assistant 消息的使用边界（硬规则）

| 用途 | 是否允许 | 说明 |
|------|---------|------|
| 作为用户事实来源 | ❌ | 旧流萤转述的"你做过 X"不是用户地面真相 |
| 作为风格/人格来源 | ❌ | 旧人格不能回流进 Character |
| 作为关系数值来源 | ❌ | 只有用户消息能触发感谢/约定/里程碑信号 |
| 里程碑/约定的**共指佐证** | ✅（受限） | 仅当用户消息已提出，assistant 消息仅用于确认措辞 |
| 对话归档原文（续聊/回溯） | ✅ | 原样进入迁移归档文件，不提炼 |
| 摘要素材（确定性模板） | ✅ | 只统计"话题/时长/轮数"，不复制语气 |

### 5.2 Character Style 的两层落地

| 层 | 内容 | 落地 | 自动？ |
|----|------|------|--------|
| **Tier A（安全，自动）** | 用户对**称呼/语气/长度**的偏好（"叫我小萤""喜欢短一点"） | `preference` MemoryRecord（运行时注入，塑造表达） | ✅ |
| **Tier B（人工，opt-in）** | 潜在 `personality/dialogue_policy` 调整建议（如"历史中用户常用昵称 X"） | 只读 `style_profile` 报告，展示 diff 供人审 | ❌ 默认禁用 |

**结论：`character/*.yaml` 在迁移中永不自动改写。** "Character Style" 通过 `preference` 记忆实现（这正是"记忆塑造风格、人格保持静态"的边界），Tier B 只是给人看的建议，不是自动变更。

## 6. 防止关系数值作弊

**问题本质：** 朴素做法是"看历史很亲密 → 直接 `trust=0.9, phase=companion`"。这等于（1）绕过引擎、（2）注入任意数值、（3）不可复现、不可审计，直接破坏"状态归系统引擎"这一防注入根基。

### 6.1 唯一合法路径：信号重放（replay），而非赋值

迁移**永远不写数值**，只产出一个按时间排序的 `BondSeed.signal_script`，然后用**既有** `BondStateEngine.apply(signal)` 逐条重放：

```text
BondSeed {
  signal_script: [ { type, detail?, ts, evidence_turns: [int] } ],  # 时间序
  caps: MigrationBondPolicy
}
```

```text
MigrationBondPolicy {                 # 可调，推荐默认
  max_phase: "trusted",               # 天花板：迁移最高到 trusted，永不 companion
  max_trust: 0.7,
  max_familiarity: 0.7,
  turn_signal_batch: 10,              # 每 N 轮历史 = 1 个 TURN_COMPLETED（批量折扣）
  thank_cap: 20,
  milestone_cap: 20,
  promise_cap: 20
}
```

重放后对超限字段做**裁剪（clamp 到 policy 上限）**：重放产生"引擎计算值"，裁剪只下修、不上修，且裁剪动作写进审计。

### 6.2 为什么这样就能防作弊

1. **数值永远是引擎算出来的** — `apply_bond_rule` 是唯一真相，迁移与线上走同一路径，无法"设成 0.9"。
2. **确定性、可复现** — 同一份 `BondSeed` 重放结果恒定；换机器/重跑结果一致。
3. **信号检测确定性（无远程 LLM）** — 感谢/约定/里程碑用规则检测，不靠模型主观判断。
4. **迁移天花板** — `companion` 阶段只应由**迁移后真实相处**获得，批量导入最多到 `trusted`，杜绝"导入 5000 条 → 瞬间 companion"。
5. **批量折扣** — 历史轮次的奖励远低于实时轮次（`turn_signal_batch=10`），让海量历史渐近而非爆炸。
6. **溯源审计** — 每个信号带 `evidence_turns`，`migration_audit.json` 可回答"trust 为什么是 0.4"。
7. **用户可重置** — 迁移后的 BondState 走既有 `BondStateEngine.reset()`，用户不认可即可一键归零（逃生门）。

### 6.3 实际信号与增量（以 `core/bond_rules.py` 为准）

| 信号 | 增量 | 说明 |
|------|------|------|
| `TURN_COMPLETED` | `familiarity += 0.005` | 经 `turn_signal_batch` 折扣后计数 |
| `THANKED` | `trust += 0.02` | 受 `thank_cap` 限制 |
| `CORRECTION` | `trust += 0.01` | 同上可设 cap |
| `SHARED_MILESTONE(d)` | `trust += 0.05`; `familiarity += 0.05`; 加 milestone | 受 `milestone_cap` 限制 |
| `PROMISE_MADE(d)` | 加 pending promise | 受 `promise_cap` 限制 |
| `PROMISE_KEPT(d)` | `trust += 0.08`; 移除 promise | 需历史佐证已兑现 |
| `PROMISE_MISSED(d)` | `trust -= 0.05`; 移除 promise | 需历史佐证未兑现 |

`phase = phase_for((trust + familiarity)/2)`，迁移不写 phase，由引擎派生。

## 7. 四个产物落地细节

### 7.1 Character Style

- `preference` MemoryRecord（Tier A）→ 经 `MemoryService` 导入，`source = MIGRATED`。
- `style_profile` 报告（Tier B）→ `runtime/companion/migration/style_profile.json`，只读、供人审。
- `character/*.yaml` → **不动**。

### 7.2 MemoryRecord

- 新增 `MemorySource.MIGRATED = "migrated"`（枚举只增不改），`trigger = "migration:<run_id>"`。
- 通过 `MemoryService` 的一个**可信导入通道**写入（跳过 `extract_explicit_memory_request`，但仍跑红线 + 去重 + 分类校验；不把历史伪装成"用户显式说记住"）。
- 类别默认权重/半衰期沿用 `CATEGORY_DEFAULTS`。

### 7.3 Shared Experience

三重落地，互不替代：

1. `shared_experience` MemoryRecord（叙事，语义可召回）。
2. `BondState.shared_milestones`（标签，结构化）。
3. `ConversationStore.set_summary(摘要)` + 最近 K 轮工作窗口（续聊）。

摘要用**确定性模板**生成（非远程 LLM），例：

```text
在 2025-xx 至 2026-08 间，你们围绕 [项目/生活/情感] 交流了 N 轮，
共同完成了 [里程碑1、里程碑2]，流萤应下了 M 条约定（已兑现 P 条）。
```

### 7.4 Bond Initialization

- 由 `BondSeed.signal_script` 经 `BondStateEngine.apply` 重放 → 落 `bond_state.json`（`{version:1, state:{...}}`）。
- 推荐复用 `apply()` 循环（不改引擎）；若数据量极大，可另设计 `apply_signals(sequence)` 批量方法（须保留确定性语义、引擎仍为唯一写者），列为可选优化。

## 8. 迁移后数据结构

### 8.1 迁移专用文件（新增，均在 `runtime/companion/migration/`）

```text
runtime/companion/migration/
  manifest.json           # 迁移清单（run_id / source sha256 / 时间 / 状态）
  audit.json              # 逐条溯源：信号→证据轮、丢弃原因、裁剪动作
  style_profile.json      # Tier B 人工审报告（只读）
  imported_history.json   # 历史全文归档（原样，供回溯，不进运行态 schema）
```

### 8.2 运行态写入目标（复用既有 schema，不新增字段）

**`runtime/companion/memory_records.json`**（`source` 新增 `"migrated"` 值）：

```text
{ version: 1, records: [ { ...MemoryRecord 全部字段..., source: "migrated", trigger: "migration:<run_id>" } ] }
```

**`runtime/companion/bond_state.json`**（不变）：

```text
{ version: 1, state: { phase, trust_level, familiarity_level, shared_milestones, pending_promises } }
```

**`runtime/companion/conversation.json`**（实际 schema，无 archive）：

```text
{ version: 1, sessions: { "firefly-main": { turns: [ {role,content,ts} ], summary: "..." } } }
```

### 8.3 一次迁移的完整数据流

```text
ImportedSession
  → (过滤) → 干净 turns
  → (分类) → ExtractionResult { preferences, facts, experiences, emotions, bond_seed }
  → (写入) → memory_records.json（facts/preferences/experiences/emotions）
            → bond_state.json（bond_seed 重放）
            → conversation.json（最近 K 轮 + summary）
  → (审计) → migration/audit.json + manifest.json
```

## 9. 原子性 / 幂等 / 回滚

- **快照优先** — 迁移前把三个运行态文件复制到 `runtime/companion/backup-<run_id>/`。
- **两阶段提交** — 先在 staging 目录生成全部产物，全部校验通过后 `os.replace` 原子落盘；任一失败则丢弃 staging，运行态不动。
- **幂等** — `manifest.json` 记录 `source sha256` + 已导入的 record id 集合；同一源重复迁移为 no-op（去重合并，绝不重复新增）。
- **回滚** — 从 `backup-<run_id>/` 恢复三文件；`reset()` 归零 bond；`MemoryService` 可按 `source=migrated` 一键删除本次迁移的全部记忆。
- **用户主权** — 迁移结果全部可查看（记忆面板）、可删、可清空、可导出。

## 10. 验收标准与测试矩阵

| # | 套件 | 覆盖 | 关键用例 |
|---|------|------|---------|
| M1 | 解析归一化 | 各格式解析器 | 角色/时间戳/顺序推断；缺角色降级人工队列 |
| M2 | 过滤 | 红线/噪声/矛盾/否定 | 密钥拦截；"忘掉 X"反转；矛盾取新 |
| M3 | 分类 | 决策表 | 每类样例 → 正确类别与落地 |
| M4 | 防污染 | assistant 边界 | assistant 文本不进事实/风格/信号；yaml 不被改写 |
| M5 | BondSeed | 信号检测 + 重放 | 重放结果 == 引擎逐步 apply；天花板/折扣生效；companion 不可达 |
| M6 | 写入 | 双写/幂等/回滚 | 同源重跑不重复；失败不破坏原文件；backup 可回滚 |
| M7 | 回归 | 现有套件 | 27+ 套件全绿（尤其 memory / bond / conversation / character） |

**DoD：**
1. 迁移全程**零远程 LLM**（分类/检测/摘要均可静态审计）。
2. `character/*.yaml` 迁移前后字节不变。
3. `bond_state.json` 数值只能由 `apply_bond_rule` 产生，`companion` 阶段在迁移中不可达。
4. 每一条记忆/信号可溯源到 `evidence_turns`。

## 11. 风险与开放问题

| 风险 / 开放问题 | 缓解 / 待决 |
|----------------|------------|
| 豆包导出**确切格式**未确认 | 先用真实样本锁定格式；解析层做成薄适配器，格式变化只影响 Stage 0 |
| 历史可能含大量旧人格/敏感内容 | assistant 隔离（§5）+ 红线（§4）+ 全文仅归档不进运行态 |
| 关系信号检测（感谢/约定/里程碑）准确率 | 确定性规则为主；检测不准只影响 bond 微调，可 `reset()`，且天花板限幅 |
| 可选**本地**分类器质量增强 vs 隐私 | 默认关闭；开启必须本地模型、静态可审计、永不远程 |
| `MemorySource` 是否加 `MIGRATED` | 建议加（审计清晰）；若不愿改枚举，回退用 `SUGGESTED + trigger=migration:*` |
| 批量重放性能（海量信号） | 优先 `apply()` 循环；量大再评估 `apply_signals(sequence)` |
| 迁移要不要把全文灌入对话工作窗口 | 只灌最近 K 轮（保续聊）+ 摘要；全文另存 `imported_history.json` |
