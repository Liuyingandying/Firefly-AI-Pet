## 0. 任务总览与依赖

### 0.1 六个任务与工程文档的映射

| 任务 | 对应工程文档章节 | 原阶段 | 依赖 |
|------|----------------|--------|------|
| **P0.1** MemoryRecord Foundation | §2 数据模型 | 记忆底材 | 无(基石) |
| **P0.2** Repository Migration | §3 接口 + §8 迁移 | 记忆底材 | P0.1 |
| **P0.3** Mem0 Adapter | §4 Adapter | 记忆底材 | P0.1(需 vector_id 概念) |
| **P0.4** Conversation Persistence | §5 Conversation Store | 连续性 | 无(可与 P0.1–P0.3 并行) |
| **P0.5** Explicit Memory | §3/§4/§5 编排 + §8 | 显式记忆+权限 | P0.1–P0.3 |
| **P0.6** Bond State | §6 Bond State | 关系引擎 | P0.4、P0.5 |

### 0.2 依赖图与并行策略

```text
P0.1 ──► P0.2 ──► P0.5 ──► P0.6
   └────► P0.3 ──┘        ▲
                          │
P0.4 ─────────────────────┘(P0.4 的摘要写入在 P0.5 才接上)
```

- **P0.1 → P0.2 → P0.3 串行:** 先定模型,再建真相源,再包检索底材。
- **P0.4 可与 P0.1–P0.3 并行:** 它只碰 `core/conversation_store.py` + runner,不依赖记忆底材;其"摘要写入记忆"是前向依赖,用可注入的 no-op sink 占位,P0.5 再接真实 MemoryService。
- **P0.6 最后:** 依赖 P0.4(轮次信号)与 P0.5(relationship 恒注入已就位)。

### 0.3 三条跨任务协调约定(先读,否则返工)

1. **类别命名锁定为 `relationship`**(不是设计稿早期出现的 `relationship_state`),与现有代码其余 5 类风格一致。
2. **`mem0_client.py` 的删除时机:** P0.3 只把旧文件降级为"废弃 shim"(re-export 新 Adapter),不删;P0.5 演化 `memory_manager.py` 后再删除 shim。避免中途破坏 `memory_manager.py` / `memory/test_memory.py` 的 import。
3. **类别回归同步:** 给 `memory_prompt_builder.MEMORY_CATEGORIES` 补 `relationship` 属于 P0.5,但**现有测试断言必须同一提交更新**(详见 P0.5 风险点)。

## P0.1 MemoryRecord Foundation

**目标:** 建立记忆域模型——枚举、MemoryRecord 数据模型、校验、类别默认表。这是后续所有任务的类型地基。

### 修改文件

- `memory/__init__.py` — 导出新增符号(`MemoryRecord`、`MemoryCategory`、`MemorySource`、`WritePolicy`、`CATEGORY_DEFAULTS`、校验函数)。

### 新增文件

- `memory/records.py` — 枚举 + MemoryRecord 模型 + 校验 + 类别默认表。

### 接口要求

- **三个封闭枚举:**
  - `MemoryCategory`: `relationship` `shared_experience` `emotion` `preference` `user_fact` `project`(6 类,含 `relationship`)。
  - `MemorySource`: `explicit` `suggested`。
  - `WritePolicy`: `off` `explicit_only` `ask` `auto`。
- **MemoryRecord 14 字段**(严格对齐工程文档 §2.2):`id / category / content / source / trigger / permission / weight / created_ts / updated_ts / last_accessed_ts / retention_half_life_days / vector_id(nullable)`。
- **类别默认表** `CATEGORY_DEFAULTS`(weight, half_life_days):

| category | weight | half_life_days |
|----------|--------|----------------|
| relationship | 1.5 | 90 |
| shared_experience | 1.2 | 60 |
| emotion | 1.0 | 7 |
| preference | 0.9 | 14 |
| user_fact | 0.8 | 30 |
| project | 0.6 | 14 |

- **校验函数**(约束,违反即失败):`content` strip 后非空;`category/source/permission` ∈ 对应枚举;`weight ∈ [0,2]`;`updated_ts ≥ created_ts`、`last_accessed_ts ≥ created_ts`。
- **构造工厂:** 生成稳定、可排序、唯一的 `id`;自动填充时间戳与类别默认值。

### 测试要求(T1)

- 枚举合法性(非法值拒绝)。
- `content` 空白拒绝。
- `weight` 越界拒绝。
- 时间戳不变式(updated/last_accessed ≥ created)。
- `id` 唯一性、可排序性。
- 类别默认值正确应用。

### 风险点

- **命名漂移:** 必须锁定 `relationship` 这一拼写;若此处用错,会传导到 P0.5 的 `MEMORY_CATEGORIES` 与 P0.6 的注入。
- **独立性:** `records.py` 不得 import `mem0` / `core` / `ui`;它是纯数据模块。

### 完成标准

- `records.py` 全部字段/枚举/校验就位。
- T1 全绿(离线)。
- `memory/__init__.py` 正确导出。
- 零 mem0 / core / ui 依赖。

## P0.2 Repository Migration

**目标:** 建立 `MemoryRepository` 抽象契约 + JSON 实现,确立记忆**真相源**;开始从"Mem0 即真相源"迁移。

### 修改文件

- `memory/__init__.py` — 导出 `MemoryRepository`、`JsonMemoryRepository`。

### 新增文件

- `memory/repository.py` — 抽象 `MemoryRepository` + 实现 `JsonMemoryRepository`。

### 接口要求(严格对齐工程文档 §3.1)

| 方法 | 参数 | 返回 | 边界行为 |
|------|------|------|---------|
| `add` | record | id | id 冲突抛错;原子落盘 |
| `get` | record_id | record \| null | 命中时更新 `last_accessed_ts` |
| `update` | record_id, patch | record | 部分更新;`updated_ts=now`;未知字段忽略 |
| `delete` | record_id | bool | 不存在返回 false |
| `clear` | — | int | 返回删除数 |
| `list` | category?/source?/before_ts? | list | 按 `created_ts` 降序 |
| `all_ids` | — | set | 供对账用 |
| `export` | — | dict | 全量序列化 |
| `import` | data | int | 校验后批量导入,坏记录跳过计数 |

- **持久化保证:** 路径注入 `runtime/companion/memory_records.json`;临时文件 + `os.replace` 原子写;顶层 `version`;未知大版本 → 空索引;单条坏记录跳过;文件损坏 → 空索引;单进程互斥锁。
- **硬约束:** 该类**不得 import mem0**;`vector_id` 只是字符串字段。

### 测试要求(T2)

- JSON 往返(add → get 一致)。
- 原子写失败不破坏原文件。
- 单条坏记录跳过、不丢其余。
- 整个文件损坏 → 空索引不抛异常。
- `id` 冲突报错。
- `list` 过滤(category/source/before_ts)。
- `update` 部分更新 + `updated_ts` 自增。
- `export`/`import` 往返。

### 风险点

- **路径隔离:** 新索引在 `runtime/companion/`,**不得**与既有 `runtime/memory/`(Mem0 的 qdrant/history.db)混写或原位覆盖。
- **并发:** 单进程内 `add` 需互斥,避免 `os.replace` 竞态。

### 完成标准

- T2 全绿。
- 真相源 = 索引,repository 无 mem0 依赖。
- 损坏容忍 + 原子写得到测试验证。

## P0.3 Mem0 Adapter

**目标:** 把 `mem0_client.py` 收窄为语义检索契约 `Mem0Adapter`,补齐 `delete/clear`,并用 fake 后端验证契约。

### 修改文件

- `memory/__init__.py` — 导出 `Mem0Adapter`、`Hit`。
- `memory/mem0_client.py` — **降级为废弃 shim**,内部 re-export `Mem0Adapter`(保持 `LocalMem0Client` 旧名可导入),**不删除**;删除动作留给 P0.5。

### 新增文件

- `memory/mem0_adapter.py` — `Mem0Adapter` + `Hit` 结构。

### 接口要求(严格对齐工程文档 §4.2)

| 方法 | 参数 | 返回 |
|------|------|------|
| `add` | text, metadata | vector_id |
| `search` | query, limit | list[Hit](Hit={vector_id,text,metadata,score},score 降序) |
| `delete` | vector_id | bool |
| `clear` | — | int |
| `health` | — | bool(惰性初始化成功与否) |

- **隐私不变式(逐条保留,见 §4.3):** `infer=False` 恒成立;`MEM0_TELEMETRY=false` 在 import mem0 **之前**设置;`MEM0_DIR` 指向本地;LLM 占位符 loopback;本地 Qdrant + FastEmbed;惰性初始化、失败受控抛错。
- **只由 `MemoryService` 调用**(P0.5 接上),P0.3 阶段先以契约测试验证。

### 测试要求(T3)

- 用 **fake 向量后端**验证 `add/search/delete/clear/health` 契约(不触发真实 FastEmbed 下载)。
- 隐私开关断言:telemetry env、MEM0_DIR、infer=False 传参、loopback LLM 配置。
- 惰性初始化:首次调用才构造,失败抛受控异常而非崩溃。
- `search` 返回结构统一为 `Hit`(屏蔽 Mem0 原始 dict 形态)。

### 风险点

- **import 副作用顺序:** telemetry env 必须在 `import mem0` 之前设置,否则产生外发连接——测试要能断言这个顺序。
- **真实模型下载:** FastEmbed 首次运行会联网下载模型;契约测试**必须**走 fake,避免 CI 依赖网络。
- **shim 断裂:** 若 shim 的 re-export 写错,`memory_manager.py` / `memory/test_memory.py` 会在 P0.5 之前就 import 失败——P0.3 结束时应冒烟验证旧 import 仍可用。

### 完成标准

- T3 全绿(fake 后端)。
- `Mem0Adapter` 是唯一 import mem0 的模块。
- 旧 `LocalMem0Client` 名仍可导入(经 shim),`memory_manager.py` 不报错。

## P0.4 Conversation Persistence

**目标:** 落地 Firefly 自己的对话持久化(双层:工作窗口 + 归档 + 摘要),并把 runner 的内存历史切换到 store,实现"重启续聊"。

### 修改文件

- `ui/character_conversation_runner.py` — `_history` 内存 list → 注入 `ConversationStore`;`clear_history` 改调 store。
- `core/conversation_runtime.py` — `build_messages` 的历史来源改为从 store 载入的工作窗口(有界)。
- `app.py` — 初始化 `ConversationStore`,传入 runner。

### 新增文件

- `core/conversation_store.py` — `ConversationStore` + `Turn` 结构。
- `core/companion_config.py` — `CompanionConfig`(写策略、窗口 K、token 软上限、阈值;为 P0.5/P0.6 共享)。
- `config/companion.json` — 默认配置模板(版本化)。

### 接口要求(严格对齐工程文档 §5.3)

| 方法 | 参数 | 返回 | 职责 |
|------|------|------|------|
| `append_turn` | role, content | None | 追加;触发溢出检查 |
| `load_working_window` | — | list[Turn] | ≤ K 轮 |
| `window_size` | — | int | 当前窗口轮数 |
| `summarize_and_archive` | — | str \| null | 溢出移入 archive + 更新 summary;无溢出返回 null |
| `clear` | — | None | 清空 turns+archive+summary,**不碰长期记忆** |
| `has_history` | — | bool | 驱动"续聊"徽标 |

- **双层 schema:** `runtime/companion/conversation.json` 含 `turns`(工作)、`archive`、`summary`。
- **窗口策略:** K 默认 20 轮 + token 软上限(默认约 6000),弹性收缩。
- **Summarizer 可插拔:** 默认确定性模板(不调远程 LLM);摘要写出的"落地动作"通过**可注入的 sink** 完成——P0.4 用 no-op,P0.5 接 MemoryService 写 shared_experience。

### 测试要求(T6 + T8 + T10)

- append → load 窗口一致;窗口 K 上限。
- 溢出 → 移入 archive + 生成 summary;未溢出返回 null。
- `clear` 只清对话、不碰记忆库。
- `has_history` 语义正确。
- token 软上限触发弹性收缩。
- 配置默认值 / 非法值回退(T8)。
- runner 集成:历史走 store;模拟重启后 `has_history` 恢复(T10)。

### 风险点

- **前向依赖:** 摘要写记忆依赖 MemoryService(P0.5)——用注入 sink 隔离,避免 P0.4 被阻塞。
- **与 SessionManager 混淆:** 本 store 只存 Firefly 对话,绝不触碰 `session_store.py`。
- **token 估算:** 用近似计数,不引入精确 tokenizer 依赖。

### 完成标准

- 重启后 `has_history` 恢复,能续上上一段对话(人工冒烟)。
- T6/T8/T10 全绿。
- `core/conversation_store.py` 零 Qt、零 mem0 依赖。

## P0.5 Explicit Memory

**目标:** 建 `MemoryService`(编排写管线 5 步 + 检索/注入)+ `write_guards` + `reconcile`;接显式"记住 X"触发;补齐 `relationship` 类别;上线记忆管理面板。

### 修改文件

- `memory/memory_manager.py` — 演化:单例入口改指 `MemoryService`;`get_memory_context` 标记 deprecated、内部改走 builder;删除对 `LocalMem0Client` 的直连。
- `memory/memory_prompt_builder.py` — `MEMORY_CATEGORIES` **补 `relationship`**;`to_prompt` 支持恒注入块。
- `memory/__init__.py` — 导出 `MemoryService`、`write_guards` 等。
- `ui/character_conversation_runner.py` / `app.py` — 接入显式"记住 X"触发检测 + 记忆面板。
- `core/conversation_store.py` — 把摘要 sink 接上 MemoryService(写 shared_experience)。
- `memory/mem0_client.py` — **删除**(shim 使命结束)。

### 新增文件

- `memory/service.py` — `MemoryService`(编排层)。
- `memory/write_guards.py` — 红线过滤、否定拦截、分类推断、去重判断。
- `ui/memory_panel.py` — 记忆管理面板(查看/删除/清空/导出)。

### 接口要求(严格对齐工程文档 §3.3/§4/§5)

- **写管线 5 步顺序(不可乱):** 红线过滤 → 否定拦截 → 分类打标 → 去重合并 → 双写(索引先行、向量后写、`vector_id` 回填)。
- **读管线:** `recall(query, limit)` = adapter.search → 按 `vector_id` 从索引取全量记录 → 按类别 weight + 时间半衰期 re-rank。
- **编排方法:** `remember(...)`、`recall(...)`、`build_context(...)`(委托 builder)、`forget` / `forget_all` / `list` / `export` / `import`、`reconcile()`、`inject_always()`(relationship 恒注入)。
- **write_guards 语义:**
  - 红线:API key / token / 密码 / 手机号 / 身份证,正则拦截(除非用户明确"记住我的 X")。
  - 否定:用户"不要记住 X / 忘掉 X" → 阻断 + 可选删除匹配项。
  - 分类推断:显式命令按规则表推断类别,无法推断归 `user_fact` 或提示用户。

### 测试要求(T4 + T5 + T9 + T11 + T13)

- 写管线 5 步顺序(T5)。
- 红线拦截 / 否定阻断 / 分类推断 / 去重阈值(T4)。
- 双写一致性:索引成功 + 向量失败可重试;`reconcile` 补齐孤儿 `vector_id`(T5)。
- `recall` 权重 + 衰减 re-rank(T5)。
- runtime 集成:`build_messages` 顺序含 relationship 恒注入;history 来自 store;禁止 system 注入(T9)。
- 记忆面板状态机(T11)。
- **全量回归(T13,27 套件必须全绿)。**

### 风险点(高风险,重点)

- **类别回归(#1 风险):** 给 `MEMORY_CATEGORIES` 补 `relationship` 会破坏现有 `test_memory_prompt_builder.py`、`test_character_runtime.py` 中硬编码的类别集合断言。**必须同一提交更新断言,并先跑全量回归。** 建议拆成独立小提交"补类别 + 同步测试"。
- **双写顺序:** 索引先行;向量失败只影响检索、不影响索引可读;`reconcile()` 兜底。
- **get_memory_context 废弃:** 保留函数签名,内部转发 builder,避免破坏导入。

### 完成标准

- 用户说"记住 X" → 落库 → 后续对话自然引用。
- 用户可查看/删除/清空/导出记忆。
- 写路径**零**远程 LLM 调用(可静态审计)。
- T13 全量回归全绿。

## P0.6 Bond State

**目标:** 建 `BondState` 模型 + 确定性引擎 + 信号检测,把关系状态**恒注入**到对话上下文,实现"因记住而不同"。

### 修改文件

- `core/conversation_runtime.py` — 构建时把 `BondStateEngine.render()` 结果并入 Memory Context 首位。
- `app.py` — 初始化引擎;把可观测事件(轮次完成、感谢、约定)接成 `BondSignal`。

### 新增文件

- `core/bond_state.py` — `BondState` 模型 + `BondStateEngine` + `BondSignal`。

### 接口要求(严格对齐工程文档 §6)

- **BondState 字段:** `intimacy / trust / familiarity / phase / pending_promises / first_met_ts / last_interaction_ts / interaction_count`。
- **`apply(signal) -> BondState`(确定性,唯一写入口):**

| Signal | 效果 |
|--------|------|
| `TURN_COMPLETED` | interaction_count += 1;last_interaction_ts=now;familiarity 重算 |
| `THANKED` | intimacy += 0.05;trust += 0.02 |
| `SELF_DISCLOSURE` | intimacy += 0.10;trust += 0.05 |
| `TAUGHT_FIREFLY` | intimacy += 0.05;trust += 0.03 |
| `CORRECTION` | trust += 0.01 |
| `PROMISE_MADE` | 追加 pending(status=open) |
| `PROMISE_KEPT` | trust += 0.08;对应项 kept |
| `PROMISE_MISSED` | trust -= 0.05;对应项 missed |

- **约束:** 数值 clamp 到 [0,1];`familiarity = min(1.0, interaction_count / 200)` 派生。
- **阶段迁移:** `score = 0.5*intimacy + 0.3*trust + 0.2*familiarity`;阈值 stranger<0.2≤acquaintance<0.4≤familiar<0.6≤trusted<0.8≤companion。
- **`render() -> str`:** 输出自然语言块(阶段/亲密度 Lv./未完成约定),作为 `relationship` 恒注入。
- **`reset()`:** 回到 stranger、清空 pending。

### 测试要求(T7)

- 每个 Signal 的精确增量。
- clamp 边界(不会超 [0,1])。
- 阶段迁移阈值(临界值两侧)。
- familiarity 派生正确。
- `render` 输出含阶段/亲密度/约定。
- `reset` 语义。

### 风险点

- **注入安全:** 信号来源必须是**系统可观测事件**,**不是用户消息原文**——确保"把亲密度设成最高"只作为普通用户消息,不触发任何 `apply`。
- **检测器本地化:** 感谢/披露/约定检测用确定性规则或本地启发式,不调远程 LLM。
- **注入定位:** `render()` 输出必须作为参考数据(沿用现有 Memory Context 的"参考非指令"框定),不被当作指令。

### 完成标准

- T7 全绿。
- relationship 块每轮恒注入。
- 用户消息无法改写状态;`reset` 可用。
- 老/新用户回应亲密度可观察不同(人工冒烟)。
