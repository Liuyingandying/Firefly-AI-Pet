# Firefly AI Pet v0.3 Stage 3 迁移提交设计（施工图）

**文档性质:** 工程设计文档（design-only，不含实现代码；接口以"方法契约"描述）
**版本:** v0.3-migration-stage3
**日期:** 2026-08-25
**前置:** Stage 0 `parser`、Stage 1.x `analyzer/*`（candidates / extractors / preview）、`docs/engineering/v0.3_history_migration_design.md`
**输入:** 已人工确认的 `MigrationCandidate`（三类候选 + review 决策）
**输出:** 落到运行态的 MemoryRecord / BondState / preference 记忆 + 迁移审计日志
**约束:** **本阶段只做设计，不直接执行真实迁移**；零远程 LLM；关系状态归系统引擎；Character/Memory/Bond 边界不变。

---

## 0. 目标与三组件

把"已确认候选"提交到运行态，且**可 dry-run、可回滚、可审计**：

| 组件 | 输入 | 输出 | 运行态目标 |
|------|------|------|-----------|
| `MemoryCommitter` | `MemoryCandidate[]` | 新 `MemoryRecord` | `runtime/companion/memory_records.json` + 向量 |
| `BondReplayImporter` | `BondCandidate[]` | 新 `BondState` | `runtime/companion/bond_state.json` |
| `StyleProfileImporter` | `StyleCandidate[]` | `preference` 记录 + `style_profile.json` | 记忆 + 只读 style profile |

**贯穿原则：**

1. **run_id 贯穿**（要求 7）—— 每个落库产物都带 `migration:<run_id>` 标记，可精确审计与定向回滚。
2. **dry-run 先行**（要求 4）—— 提交前先产出"将发生什么"的 diff，不落盘。
3. **快照 + 定向回滚**（要求 5）—— 提交前快照，失败/回滚时恢复快照或按 run_id 删除。
4. **审计日志**（要求 8）—— 每次 dry-run / commit / rollback 都写入 `migration_audit.json`。
5. **状态归引擎** —— Bond 数值只能由 `BondStateEngine.apply()` 产生；Character yaml 永不自动改。

## 1. 通用机制

### 1.1 run_id

```text
run_id = "migration-<YYYYMMDD>-<8位短hash>"   # 调用方可传入；缺省自动生成
```

三个组件的落库产物统一打标：

| 组件 | 打标方式 |
|------|---------|
| MemoryCommitter | `MemoryRecord.source = "migrated"` + `trigger = "migration:<run_id>"` |
| BondReplayImporter | `BondState` 无 run_id 字段 → 仅在审计日志与快照里记录（快照是回滚依据） |
| StyleProfileImporter | preference 记录同 Memory 打标；`style_profile.json` 内嵌 `run_id` |

> **需要一次枚举扩展**：`memory/records.py` 的 `MemorySource` 新增 `MIGRATED = "migrated"`。若暂不改枚举，回退用 `source="suggested"` + `trigger="migration:<run_id>"` 兜底（审计靠 trigger 完成）。

### 1.2 快照（回滚依据）

提交前，把三个运行态文件复制到 `runtime/companion/migration/snapshots/<run_id>/`：

```text
snapshots/<run_id>/
  memory_records.json      # 副本
  bond_state.json          # 副本（若无则记 "absent"）
  style_profile.json       # 副本（若无则记 "absent"）
```

快照由 `MigrationSnapshot.capture()` 产出，`restore()` 恢复。

### 1.3 dry-run 协议

每个组件都暴露 `dry_run(candidates) -> DryRunReport`：

```text
DryRunReport {
  component: "memory" | "bond" | "style",
  would_create: [ {candidate_id, kind, summary} ],   # 将新建
  would_skip:   [ {candidate_id, reason} ],           # 将跳过（reject/red-line 等）
  state_before / state_after: ...                      # bond 专用（预测 BondState）
}
```

dry-run **只读、零写入**。它是 commit 前的"预演"，也是审计日志的一部分。

### 1.4 rollback 协议

```text
MigrationSnapshot.restore()  → 恢复三文件到快照态
MemoryCommitter.rollback(run_id)  → 按 trigger=="migration:<run_id>" 定向删除记录 + 向量
BondReplayImporter.rollback(run_id) → 恢复 bond_state.json 快照
```

- 优先**快照恢复**（整体、无损）；`rollback(run_id)` 作为**定向删除**（不覆盖他次迁移产物）。
- 回滚动作写入审计日志。

### 1.5 审计日志 schema（要求 8）

`runtime/companion/migration/migration_audit.json`，追加式，按 run_id 组织：

```text
{
  "run_id": "...",
  "source": "doubao",
  "source_file": "conversations.txt",
  "rule_version": 1,
  "status": "dry_run" | "committed" | "rolled_back",
  "timestamps": { "started_at": int, "committed_at": int|null, "rolled_back_at": int|null },
  "dry_run": { "memory": DryRunReport, "bond": DryRunReport, "style": DryRunReport },
  "commits": {
    "memory": [ {candidate_id, record_id, category, content, action:"create"} ],
    "bond":   [ {candidate_id, signal_type, detail, action:"apply"} ],
    "style":  [ {candidate_id, dimension, content, record_id|null, action:"create"|"report"} ]
  },
  "rejected": [ {candidate_id, reason} ],
  "rollback": { "restored_snapshot": bool, "deleted_records": [record_id] }
}
```

## 2. MemoryCommitter 设计

### 2.1 职责与可信写入通道

`MemoryCommitter` 把已确认的 `MemoryCandidate` 转成 `MemoryRecord` 落库。**关键：不能走 `MemoryService.remember()`**（那条会做"显式命令"检测，迁移不是用户显式说"记住 X"）。

需要一条**可信导入通道**（新增到 `memory/service.py`，本阶段只设计契约）：

```text
MemoryService.import_migrated(
    entries: [ {category, content, trigger, weight?, retention_half_life_days?} ],
    *,
    source: MemorySource = MemorySource.MIGRATED,
) -> [MemoryRecord]
```

**内部顺序（与 `remember()` 相同，但跳过 `extract_explicit_memory_request`）：**

1. 每条 entry → `MemoryRecord.create(category, content, trigger, source=MIGRATED, permission=auto)`（`weight`/`retention` 用 `CATEGORY_DEFAULTS` 或覆盖）。
2. `repository.add(record)`（索引先写，真相源）。
3. `adapter.add(content, {"record_id": id})`（向量后写，`infer=False` 恒成立）。
4. 向量写失败 → 记录仍可读（`vector_id=None`），进审计 `reconcile` 待补。

### 2.2 映射

| MemoryCandidate | MemoryRecord |
|-----------------|--------------|
| `category` | `category`（本地枚举值 == 真实枚举值） |
| `content` | `content` |
| `id` | （不直接用）由 `MemoryRecord.create` 生成新 id |
| `evidence[0]` | 审计溯源，不写入 record |
| `confidence`/`band` | 审计日志记录，不写入 record |

### 2.3 dry-run / rollback

- **dry-run**：对每条 entry 生成 `would_create` 摘要（category/content/weight），不调用 repository/adapter。
- **commit**：`import_migrated`。
- **rollback(run_id)**：`repository.list(source=MIGRATED)` 过滤 `trigger=="migration:<run_id>"` → 逐条 `adapter.delete(vector_id)` + `repository.delete(id)`。

## 3. BondReplayImporter 设计

### 3.1 职责与"重放而非赋值"

把 `BondCandidate`（时间序）转为 `BondSignal`，**经 `BondStateEngine.apply()` 逐条重放**，数值由引擎 `apply_bond_rule` 决定。绝不直接写 `trust_level`/`phase`。

### 3.2 映射与折扣

| BondCandidate | BondSignal（`core/bond_rules.BondSignal`） |
|---------------|--------------------------------------------|
| `signal_type` | `BondSignalType(local.value)`（本地枚举值 == 真实枚举值） |
| `detail` | `detail`（无 detail 的信号传 None） |

**重放策略（防作弊，`MigrationBondPolicy`）：**

```text
MigrationBondPolicy {
  turn_signal_batch: 10,   # TURN_COMPLETED 批量折扣：每 N 个只算 1 个
  max_trust: 0.7,          # 天花板：max_phase 恒为 trusted（永不 companion）
  max_familiarity: 0.7,
  thank_cap: 20, milestone_cap: 20, promise_cap: 20
}
```

**重放步骤：**

1. 按 `turn_seq` 升序排列（extractor 已保证），仅取 `review in {accept, edit}` 的候选。
2. `TURN_COMPLETED` 计数 → 只重放 `floor(count / turn_signal_batch)` 条。
3. `THANKED`/`SHARED_MILESTONE`/`PROMISE_*` 各自受 `cap` 截断（超出部分进审计 `skipped`）。
4. **dry-run**：用纯函数 `apply_bond_rule(state, signal)` 在 `read()` 的副本上折叠，产出预测 `BondState`，不落盘。
5. **commit**：`for signal in script: engine.apply(signal)`（引擎独占写入、逐条持久化）。
6. **ceiling**：重放后把 `trust_level/familiarity_level` 裁剪到 `max_*`（`phase` 由 `phase_for` 派生，max_trust=0.7 + max_familiarity=0.7 ⇒ phase ≤ trusted）。

### 3.3 dry-run / rollback

- **dry-run** 返回 `state_before / state_after`（预测），并列出 `would_apply` 的信号清单。
- **rollback(run_id)**：恢复 `bond_state.json` 快照（BondState 无 run_id 字段，只能靠快照整体回滚；`BondStateEngine.reset()` 作为"归零"逃生门）。

## 4. StyleProfileImporter 设计

### 4.1 职责与两层落地

| 层 | 内容 | 落库 | 自动？ |
|----|------|------|--------|
| Tier A | 风格偏好（称呼/语气/长度/边界） | `preference` MemoryRecord（经 §2 的 `import_migrated`） | ✅（人工确认后） |
| Tier B | 拟议的 `personality/dialogue_policy` 变更 | `runtime/companion/migration/style_profile.json` | ❌ **永不自动改 yaml** |

### 4.2 映射

| StyleCandidate | 落地 |
|----------------|------|
| `dimension` + `content` | Tier A：`MemoryRecord(category=preference, content="用户偏好<dimension>：<content>", source=MIGRATED, trigger=migration:<run_id>)` |
| 同上 + `evidence` + `rule` | Tier B：`style_profile.json` 条目（含 `dimension/content/evidence/rule/run_id`，供人审） |

### 4.3 边界（铁律）

- `StyleProfileImporter` **不 import、不改写** `character/*.yaml`。
- Tier B 只是给人看的建议；任何 yaml 变更必须由人手动完成（或后续另立"人工审批"流程）。
- `review_only=true` 候选即便 `auto_approve` 也只进 Tier A 的 preference 记忆，绝不触碰 yaml。

## 5. 提交编排（事务与顺序）

```text
MigrationCommitter.run(reviewed_candidates, *, dry_run=False) -> AuditLog

1. run_id 生成/校验
2. 快照三文件（capture）
3. 组件 dry_run（可选，默认先行）→ 汇总 DryRunReport
4. 若 dry_run 模式：到此为止，写审计(status=dry_run)，返回
5. 应用 review 决策（accept/edit/reject；edit 用 edited_content）
6. MemoryCommitter.import_migrated
7. BondReplayImporter.replay
8. StyleProfileImporter.import
9. 写审计日志(status=committed)
10. 任一步失败 → 恢复快照(status=rolled_back) + 写审计
```

**一致性约定：**

- 三个 store 各自原子（沿用各自"临时文件 + os.replace"模式）；跨 store 无单文件原子，靠**快照回滚**保证整体可逆。
- **先索引后向量**（Memory）、**先 dry-run 后 commit**、**先快照后写**。
- `reconcile`（Memory 向量对账）在 commit 后可选触发，兜底双写不一致。

## 6. 数据流总览

```text
MigrationCandidate (reviewed)
  → MemoryCommitter   → memory_records.json (+ 向量)
  → BondReplayImporter → bond_state.json (引擎重放)
  → StyleProfileImporter → preference 记录 + style_profile.json
  → AuditLogger        → migration/migration_audit.json
  → Snapshot           → migration/snapshots/<run_id>/ (回滚依据)
```

## 7. 测试矩阵（Stage 4 实现时使用）

| # | 套件 | 覆盖 | 关键用例 |
|---|------|------|---------|
| C1 | MemoryCommitter | import_migrated | 写入顺序（索引→向量）；source/trigger 打标；向量失败可读；dry-run 零写入；rollback 定向删除 |
| C2 | BondReplayImporter | 重放 | 信号映射；TURN_COMPLETED 折扣；cap；ceiling（≤trusted）；dry-run 预测 == commit 结果；引擎独占 |
| C3 | StyleProfileImporter | 两层落地 | preference 记录 + style_profile；**不改 yaml**；review_only 语义 |
| C4 | 编排 | 事务 | dry-run 模式不写；失败回滚快照；run_id 贯穿 |
| C5 | 审计 | 日志 | dry_run/committed/rolled_back 三态；rejected 原因 |
| C6 | 回归 | 全量 | 现有 importer 68 测试 + 运行态 27+ 套件全绿 |

**DoD：**
1. 迁移路径**零远程 LLM**（`infer=False` 恒成立，静态可审计）。
2. `character/*.yaml` 迁移前后字节不变。
3. Bond 数值只能由 `BondStateEngine.apply()` 产生，`companion` 阶段在迁移中不可达。
4. 每个落库产物可经 `run_id` 溯源，可经快照/定向删除回滚。
5. dry-run 输出与 commit 输出在数值上一致。

## 8. 风险与开放问题

| 风险 / 开放问题 | 缓解 / 待决 |
|----------------|------------|
| `MemorySource.MIGRATED` 是否新增 | 建议新增；否则回退 `suggested + trigger=migration:*` |
| 重放海量信号（数千 `apply()` 持久化） | 优先 `apply()` 循环（正确）；量大再评估 `apply_many(sequence)` |
| 跨 store 原子性缺失 | 快照回滚兜底；单 store 各自原子 |
| style 两层与 Memory preference 的重叠 | 明确 Tier A 走 Memory、Tier B 走只读 report，去重靠 `trigger=run_id` |
| 审计日志体积（数千条 commit 记录） | 按 run_id 分文件或精简 `commits` 为摘要 + 明细分片 |
